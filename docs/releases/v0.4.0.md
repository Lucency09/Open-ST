# Open-ST v0.4.0

本版新增完全本地的 OCR 文字识别：框选截图后识别中英日文字，结果可编辑和复制。翻译功能尚未接入。

## 下载与运行

- **安装版**：`Open-ST-0.4.0-win-x64-Setup.exe`，支持当前用户／所有用户安装及自定义本地目录。
- **便携版**：`Open-ST-0.4.0-win-x64.zip`，完整解压后运行 `Open-ST.exe`。
- **校验文件**：`SHA256SUMS.txt`，包含上述两件资产的 SHA-256。
- 目标平台：Windows 10 22H2／Windows 11 x64。安装包内含经核验的微软 VC++ x64 运行库，缺失时请求确认；便携版需自行准备运行库。
- 程序和 Setup **未签名**，Windows 可能显示未知发布者或 SmartScreen 提示；SHA-256 不等同发布者签名。

## 相比 v0.3.0 的变化

- 截图工具栏新增“识别文字”，识别点击时已经合成标注的图像；马赛克和遮挡参与识别，不回读被遮挡原文。
- 使用 Tesseract 5.5.1 + Leptonica 1.85.0，离线附带 fast/best 两套中英日模型；默认 fast、中英日混合，可在“设置 → 文字识别”中调整。
- 后台执行识别，结果窗口支持多行编辑、复制全部及原生文本撤销；保留截图编辑器。选区修改不改变已有结果，关闭结果后可重新识别。
- 单任务准入、合作取消和晚结果保护；结果窗参与模态输入门禁，退出先等待识别资源释放再关闭日志。
- 对小尺寸输入加入有界2倍预处理，改善已测小字样例；不同字号、字体和复杂背景仍可能误识别。
- 复用公共窗口、剪贴板和 SHA-256 能力，模型与运行依赖由同一份发布清单管理。
- 构建脚本默认开启 OCR，由脚本顶部 `$EnableOcr = $true` 控制，正常构建无需额外参数；模型和依赖缓存继续复用。

## 使用与升级

- 默认 `Ctrl+Alt+Q` 截图；框选后点击工具栏末尾“识别文字”。OCR 不上传截图或文字，不需要 API Key。
- 安装版通过“关于 → 检查更新”查询，确认后下载校验并打开 Setup；便携版确认后打开版本页，自行下载、解压覆盖。
- 升级前退出使用目标目录的实例并备份 `data/`。安装器不强制结束程序，覆盖升级保留数据；便携升级保留 `data/` 并更新程序、资源和运行DLL。
- 旧 ZIP 转安装版请选新目录，再显式迁移备份数据。所有用户安装仍共享 EXE 旁数据，各用户自启登记独立。

## 验证与已知限制

- OCR 开／关的 Debug、Release `/W4 /WX` 均已通过。全量回归 **815 项：802 通过、12 条件跳过、1 项既有 D-066 失败**；没有新增失败。
- 21 项 OCR 核心用例覆盖模型、输入、线程／取消及真实引擎；7 项窗口／会话集成用例覆盖编辑、复制、晚结果与模态暂停等。
- 自有1200×800混合文字样例在开发机的 fast 热识别约220ms；这是引擎测量，不含截图准备和界面显示，不保证所有截图端到端2秒内完成。
- OCR 真实截图、中文IME、跨屏／HDR／混合DPI和安装目录离线流程尚未逐项人工验收；小字、复杂版面和密集正文的准确率与耗时存在差异。
- 原生编辑框处理极端长文本时可能停顿；100万连续字符测试曾约18秒。模型初始化及部分版面分析不保证即时取消，退出可能等待后台完成。
- D-066：贴图相对顺序正确时仍产生冗余位置请求，保留失败。复杂标注冷构建、HDR综合色彩及设备丢失恢复仍有后置事项。
- Windows 10、所有用户提权／真实多账户、缺运行库／重启、显式删除数据、跨版本覆盖安装，以及真实远端下载执行Setup完整流程，仍有实机验收缺口。
- UI Automation 子控件识别、冻结鼠标指针和翻译仍未接入。

项目采用 MIT，第三方完整许可随包提供。仅发布 Setup、ZIP、SHA256SUMS，不上传用户数据、测试日志或含开发机路径的构建记录。

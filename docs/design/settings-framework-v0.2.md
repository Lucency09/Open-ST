# 0.2.0 设置窗口框架设计

状态：已由用户批准的 [Settings JSON 窗口与绑定方案](settings-renderer-v0.2.md) 替代，本文仅保留历史设计。日期：2026-09-08。
范围：实现进度“0.2.0 阶段安排”第1步。依据：开发规范、D-045、D-052及当前Settings实现。

## 1. 目标与本轮边界

将现有仅含语言选择的小窗口改为可逐步扩展的原生设置窗口，建立统一草稿、提交、取消和恢复默认规则。
本轮只有“常规”页及界面语言设置；后续自启加入常规页，快捷键、截图、存储、维护在实际功能接入时增页。
不预建空页，不在本轮实现自启、快捷键管理、冻结指针、日志清理、关于页或其他设置业务。
首轮保留现有Win32、系统字体和A2图标；不增加第三方UI框架，不改Common或模块依赖方向。

## 2. 现状与需要解决的问题

- SettingsWindow是单个非模态窗口，重复打开仅激活已有窗口；现有布局为420×190设计单位且不能调整大小。
- 当前语言选择只在确定时通过SetStringSetting写入，取消不写入；窗口没有独立草稿和页面容器。
- 当前Apply重新生成语言列表时，若原选择消失，会自动选中英文或第一项并继续保存，可能改变用户意图。
- languageApplied目前返回void，Application忽略SetUiLanguage的失败结果；不能区分已保存与已生效。
- Settings单键写入已使用Common锁内编辑并保留未知字段，但没有编辑基线或窗口期间同键修改冲突检查。
- 当前默认设置资源只有ui.language和capture.selection_border_color；本轮恢复默认仅涉及语言，不重置整个文件。

## 3. 窗口与布局

建议初始客户区600×360，最小客户区480×280，以上均以96 DPI为基准。随显示器工作区约束实际尺寸；
若工作区不足容纳最小设计尺寸，优先保证窗口和底部按钮可达，页面区域提供滚动，不强行超出屏幕。
允许调整窗口大小，保留单实例非模态行为、系统标题栏、系统配色、现有图标与系统支持的圆角。
首次显示在当前用户操作所在显示器工作区内居中；重复打开只激活并保留当前草稿。

布局示意（初始只有一个标签，后续按已实现业务添加）：

```text
┌ 设置 ────────────────────────────────────────────┐
│ [常规]                                           │
│                                                  │
│   界面语言      [ zh-CN                       ▾ ] │
│   保存后应用界面语言。                           │
│                                                  │
│   （必要时显示校验、保存或生效失败信息）           │
│                                                  │
│ [恢复本页默认]             [确定] [取消] [应用]    │
└──────────────────────────────────────────────────┘
```

- 顶部采用原生标签控件，内部使用独立页面容器；本轮具体实现常规页，不设计插件式页面注册系统。
- 页面容器与窗口框架分开负责控件和布局。页面切换只换显示内容，不触发保存；所有草稿归窗口级编辑会话。
- 系统字体、边距和控件按当前DPI重排；长文本参与测量/换行，底部按钮不重叠。
- Tab/Shift+Tab遍历可见控件，标签支持键盘切换；下拉框展开时Enter/Esc先处理下拉框，不误提交/关窗。
- 页容器按非模态对话框导航要求组织；跨DPI更新字体、布局及滚动范围，保持焦点和草稿。
- 所有用户文本经Application注入的GetUiText回调获取，新增文本同步中英日资源。

## 4. 编辑和按钮行为

| 操作 | 行为 |
| --- | --- |
| 打开窗口 | 读取可靠的用户字段基线和显示值，建立内存草稿。读取失败显示错误并禁用提交，可重试读取；不以默认回退冒充有效用户文件。 |
| 修改语言 | 只更新草稿，不改文件、不即时切换语言。语言代码仍动态发现，不维护固定语言清单。 |
| 应用 | 校验并提交全部已修改字段；持久化成功后应用语言，刷新设置窗口、托盘等现有界面，窗口保持打开。无修改且无待应用结果时禁用。 |
| 确定 | 执行同一提交流程，全部成功后关闭；无修改且无待应用结果时直接关闭，不额外写盘。 |
| 取消、Esc、右上角关闭 | 丢弃尚未提交的草稿并关闭，不再追问；之前点击应用已保存的内容不会撤销。 |
| 恢复本页默认 | 先确认，确认后只将当前页草稿改为默认资源中的值；仍需应用或确定才保存。此次仅恢复语言，不碰选框颜色、保存目录或未知键。 |
| 校验/保存失败 | 保留窗口、草稿和原持久化基线，显示原因类别；允许修正或重试，详细错误写日志。 |
| 外部同键冲突 | 不覆盖外部新值，保留草稿并提示；提供“重新加载”，确认丢弃本轮草稿后读取最新状态，不自动强制覆盖。 |

窗口忙于提交或确认提示时防止重复提交及销毁重入；检查资源或校验时不在Common编辑回调内调用UI或本地化。
本轮语言保存是同步的小规模操作，不新增后台线程或轮询。

## 5. 动态语言与恢复默认

打开窗口、展开下拉框和提交前按现有方式查询可用语言。用户明确选中的语言若消失，保留该草稿意图，
显示不可用并阻止保存，直到用户重新选择可用语言。不能自动改选其他语言后保存。
读取失败且无可靠可用列表时禁用提交；Localization现有最后有效业务快照及告警规则保持不变。
Application的availableLanguages回调先通过现有IsUiTextAvailable确认当前或最后有效快照可用，
不可用返回空列表，可用才查询GetAvailableUiLanguages；不能把后者兜底返回的en-US当作资源有效证据。
已存语言在当前列表中不可用时也明确展示这一状态，不通过无修改的确定按钮偷偷重写配置。
无修改且无待应用结果时，“确定直接关闭”优先于语言校验，不阻止用户正常退出。

恢复默认通过Settings默认资源句柄读取ui.language（当前资源为en-US），不使用运行时语言充当默认值。
默认文件不可读、字段缺失、类型错误或语言不可用时只提示，不改草稿，不硬编码另一项替代。
恢复仅作用于本页已实现字段；后续全局恢复默认和系统副作用在相应业务方案中明确，不扩大本轮范围。

## 6. 保存与生效边界

Settings内部增加私有编辑会话，管理动态字符串键、原始基线和草稿；仅实现当前语言实际需要的能力。
不新增公开JSON快照、设置键枚举、全类型注册表或跨模块事务框架；保留现有公开Get/Set*Setting接口。
未来多字段页面接入时沿用一次提交入口，按实际需求扩展类型和字段，避免各控件各自立即写盘。

提交顺序：

1. 在锁外完成页面业务校验与可用语言检查，形成所需修改字段。
2. 通过同一次Common句柄Write编辑回调，在锁内读取最新用户文档并验证结构。
3. 对每个已编辑字段比较其原始存在性、类型和值；最新值等于打开基线或等于目标值才允许提交，否则报告冲突。
4. 只修改本次字段，其余键及外层未知字段按最新文档保留；用户文件缺失、损坏或访问失败时不重建或覆盖。
5. 写入成功后更新持久化基线。写入失败不发布新基线、不调用语言应用回调。
6. 离开存储锁后通过Application应用所选语言，回调返回成功/失败并刷新实际生效语言对应的UI。

这只能保证单文件提交的既有安全语义，不承诺配置文件和运行时副作用是一个原子事务，也不保证后续外部编辑不再发生。
如果文件已保存但语言切换失败，明确提示“设置已保存，但语言未能生效”，保留窗口并记录待应用状态。
当前SetUiLanguage失败可能回退英文，因此不能宣称运行时必然保留旧语言；UI按实际运行语言刷新。

草稿未再修改时，“应用”重试仅执行语言应用，不重复写文件；重试前核对保存字段仍为目标值并重新检查语言。
字段已被外部改变则转入冲突处理。用户也可选择其他可用语言重新提交；取消/关闭不撤销已保存结果。
文件原先不可读时，重试加载成功才建立基线；重试失败不解禁提交。

## 8. 施工顺序与验收

施工顺序：私有编辑与条件保存 → 窗口壳/常规页 → 操作状态和应用回调 → 本地化/DPI/键盘 → 验证与文档。
施工期间由子Agent监督；实质偏离本方案时重新提交审核。

- 存储回归：取消不写、恢复默认只改草稿、一次提交、无关键/保存目录保留、同键冲突、目标值已一致、
  原始缺失/类型差异、用户文件删除/损坏/只读、默认资源错误及失败后重试。
- 语言回归：动态新增/删除语言、提交前失效、持久化成功才通知、通知失败不冒充保存失败、重试不重复写盘。
- 窗口回归：单窗口重复打开保留草稿、确定/取消/应用、保存后仍可继续编辑、关闭/重建与资源生命周期。
  控件迁入页面后调整测试定位；提交错误逻辑使用私有测试入口，避免模态提示堵住自动测试。
- 人工检查：中英日及长译文、100%/150%/200% DPI、跨屏、缩放/小工作区、键盘与下拉框焦点、恢复默认确认。
- 本轮只有一个真实页，多页切换的实际UI集成验证在后续新增真实页面时补齐，不虚报多页已验收。
- Debug/Release产品构建及与改动相称的模块测试；最终diff、输出目录和文档一致性检查。

## 9. 设计复核

独立子Agent已只读检查当前源码和约束，认可总体方向；本稿纳入其要求：私有最小编辑能力、原始字段冲突检查、
保存/生效分离、默认资源失败保护、动态语言意图保留及真实窗口测试边界。最终仍待用户批准后施工。

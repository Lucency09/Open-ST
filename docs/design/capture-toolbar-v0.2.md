# 截图工具栏方案

状态：用户已批准，代码与自动验证已完成，完整人工验收待确认。日期：2026-09-09。依赖、命令防重入及按钮扩展设计已由子 Agent 审核；最终验证进度见 [实现进度](../implementation_progress.md)。

## 1. 范围与现状

用户指定按参考图设计选区附近的紧凑横向工具栏，本次将工具栏设计前移；进度表原有快捷键管理、截图与存储设置等事项继续保留。
现有 App::CopySelection/SaveSelection 已统一处理快捷键和输出，Selected 阶段具备稳定选区；保存取消或失败保留冻结帧及选区。

首版仅提供取消截图、保存、复制，顺序为“取消 | 保存 复制”。参考图中的标注、撤销/重做、贴图等随业务实现再加入，不显示空功能按钮。
本轮不修改选框颜色、控制点样式、导出算法、快捷键配置或字体设置。

## 2. 外观

- 采用参考图的浅灰横条、单色线条图标、细边框和垂直分隔线，不使用带标题栏的普通对话框。
- 初始视觉参数：背景 #F4F4F4、图标 #454545、外框淡蓝 #65B5E8；高度 34 DIP，按钮命中区 30×28 DIP，图标 16 DIP，外侧圆角 3 DIP。
- 悬停为淡蓝底，按下加深；按钮无常驻文字，悬停显示本地化名称和现有快捷键。图标用本地矢量绘制，不依赖符号字体或下载资源。
- 取消采用叉号，保存采用软盘，复制采用重叠方框；复制放在最右侧。首版宽度按实际三个按钮收缩，后续业务向左扩展。
- 提示文字暂沿用系统字体；用户要求的可配置字体已是独立低优先级待办。

## 3. 交互与位置

- 未选区或拖动创建、移动、缩放时隐藏；松开鼠标形成有效 Selected 选区后显示。
- 每次完成选区操作时，以松开鼠标所在且与选区相交的屏幕为目标；必要时回退到与选区相交面积最大的屏幕。仅显示一条工具栏，普通鼠标移动不重新选屏。
- 优先放在选区下方靠右，距控制点命中区至少 6 DIP；下方放不下则改为上方。水平位置约束在目标屏幕工作区，均放不下时回退到工作区内并尽量避开控制点。
- 使用目标屏 DPI 将 DIP 尺寸转换为物理像素；选区保持原有虚拟桌面物理坐标，支持负坐标和不连续屏幕布局。
- 工具栏跨屏引起的自身 DPI 更新仅重建尺寸与图标；真实显示布局变化仍走现有截图会话失效流程。
- 点击取消直接结束此次截图并返回桌面。Esc/右键保持原有“取消拖动 → 清空选区 → 结束截图”语义；取消按钮提示为“取消截图”，不把 Esc 标成完全等价快捷键。
- 保存和复制复用现有 App 入口；输出成功关闭截图。保存取消、输出失败且会话仍有效时，在对话框结束后恢复工具栏、选区及原有焦点。
- 工具栏及提示窗在输出、保存对话框和错误提示期间隐藏。连续点击仅接受一次；鼠标按下后移出按钮再释放不触发动作。

## 4. 模块与接口

新增 src/Launcher/Application/CaptureToolbar，独立目标 OpenST::CaptureToolbar，测试镜像为 testing/test/Launcher/Application/CaptureToolbar。

模块负责工具栏窗口、布局、图标、按钮状态、提示和命令通知。App 拥有实例并协调会话，模块不直接依赖兄弟 Graphics、Settings、Localization、Export，不读写 JSON。
Common/WindowRenderer 当前提供 JSON 表单窗口，本轮保持其职责；截图工具栏采用专用无激活 owned popup 和自绘原生按钮。

接口草案（具体签名施工时按工程规范细化）：

```cpp
enum class CaptureToolbarCommand { Cancel, Save, Copy };

// 创建时注入 owner、文本解析和命令通知；创建失败返回明确结果。
Create(owner, buttonSpecs, textResolver, onCommand);
// App 将选区快照适配为 RECT 等基础数据，不暴露 Graphics 类型。
UpdatePlacement(selectionRect, monitorWorkArea, dpi);
Show(sessionToken);
Hide();
SetBusy(bool busy);
UpdateButtonStates(states);
RefreshTexts();
Close();
```

App 注入文本解析器，读取 ui_text.json 中 capture.toolbar.* 键；RefreshLocalizedUi 同步刷新按钮可访问名称和悬停提示，提供中、英、日文。
命令使用固定类型和数值会话标识，通过 App 消息队列分派，不从按钮回调栈直接销毁窗口。
App 校验会话标识、当前 Selected 状态及忙状态；旧消息不得作用于后来新建的截图。投递时立即锁定按钮，拒绝重复请求，投递失败恢复可交互状态。

### 4.1 依赖专项审核

2026-09-09 主 Agent 与子 Agent 独立审核：目录位置和依赖方向通过。实现目标已建立，独立工具栏测试编译、链接及自动用例通过，链接列表符合下列约束。

- Application 通过 PRIVATE 链接 OpenST::CaptureToolbar；由 Application/CMakeLists.txt 声明直接子目录，工具栏自己的 CMake 管理源码和公开头。
- CaptureToolbar 仅使用 C++ 标准库、Windows SDK 和 open_st_project_options。编译配置目标为 PUBLIC；首版 GDI 图标、自绘原生按钮和提示使用 user32、gdi32、comctl32，均为 PRIVATE 链接。
- 首版不链接 Common 或 Common/WindowRenderer，不使用 JSON、D3D、DXGI、HDR 或导出资源；错误以工具栏自有结果返回 App，由 App 记录日志并显示本地化提示。
- 不得依赖祖先 Application，也不得直接或通过其他目标间接引入兄弟 Graphics、Capture、Settings、Localization、Export、SystemIntegration。禁止包含其公开/私有头或借用其 include 路径。
- 公开接口仅使用标准库、HWND/RECT/UINT 等 SDK 基础类型及工具栏自有命令、状态和结果。SelectionSnapshot、RectI、冻结帧及 App 指针不进入接口，适配全部在 App 内完成。
- 命令回调建议为 std::function<bool(CaptureToolbarCommand, std::uint64_t)>，返回投递是否成功。App 的 lambda 持有消息编号并执行 PostMessage；工具栏不包含 app.h 或 Application/private/resource.h，也不调用 App 成员函数。
- 文本解析回调返回拥有数据的 std::wstring；工具栏保存按钮和提示字符串，避免借用临时 c_str。所有接口及回调限 UI 线程，Close 解除回调后才能释放拥有者。
- 工具栏单元测试只链接自身目标、GTest 和必需 SDK 库，通过伪命令与文本回调验证；App 集成测试另外验证坐标适配和业务分派，不让单元测试借完整 Application 掩盖隐藏依赖。
- PRIVATE 约束实现使用要求的公开程度，但静态库所需的 SDK 库仍可能作为最终可执行文件的链接依赖传递；不将 PRIVATE 误解为完全没有传递链接需求。

已检查目标链接关系和 include 引用，独立工具栏测试目标无需链接 Application 或其他兄弟模块即可完成链接。

### 4.2 按钮扩展设计

工具栏按 App 提供的有序按钮描述列表创建，不把三个按钮的顺序、坐标、宽度写进窗口事件处理器。
描述和状态类型由 CaptureToolbar 自己定义，继续保持上述依赖边界：

```cpp
struct ToolbarButtonSpec
{
    CaptureToolbarCommand command;
    ToolbarIcon icon;
    std::string tooltipKey;
    std::uint32_t group;
};

struct ToolbarButtonState
{
    CaptureToolbarCommand command;
    bool visible;
    bool enabled;
    bool checked;
};
```

- App 注册首版 Cancel、Save、Copy 三项，取消独立分组；描述按值保存。命令 ID 唯一并校验，未知 ID 或无效图标返回明确错误，按钮位置下标不充当命令身份。
- 工具栏按列表统一创建、布局、命中和更新提示；组号仅标记分组，不按组号重排。隐藏项不占宽度，分隔线根据相邻可见组生成，避免首尾或连续空分隔线。
- visible/enabled/checked 为 App 下发的业务状态，hover/pressed 为工具栏自身交互状态。checked 只显示已确认的当前工具；未来画笔、箭头、文字的互斥由 App 协调标注业务，不由按钮自行决定。
- 处理点击只通知命令，不内置导出或结束截图。未来画笔选择、撤销、重做等可以保持截图，复制和保存仍由 App 根据业务结果决定收尾。
- 工具栏投递和快捷键进入同一 App 命令准入逻辑，统一检查待处理、忙状态、截图会话及选区操作代次。投递后立即锁定入口，旧命令失效，保存取消后不执行残留重复请求；不能只禁用工具栏而漏掉快捷键。
- 未来按钮分组方向为“标注工具 | 撤销/重做 | 取消、贴图等结果操作 | 保存、复制”。只在业务可用时注册；这是扩展顺序，不是本轮全量按钮承诺。
- 新增普通按钮需要增加命令枚举、图标、文本、App 注册及业务分派，布局和命中机制保持共用；明确是代码层扩展，不承诺仅修改 JSON 即可添加新业务。
- 颜色、线宽和下拉选项等复合控件在对应业务设计时再扩展呈现形式，不预建空浮层。按钮增多后优先保留保存/复制等完成操作，其他组通过“更多”收纳；溢出交互随首个需要它的扩展另行审核，首版不添加空“更多”按钮。

子 Agent 已审核按钮扩展方案。验收补充唯一 ID 校验、隐藏项/分组布局和状态更新；复合按钮与窄屏溢出的未实现部分不记为已支持能力。

## 5. 窗口与资源约束

- 在覆盖窗口全部建立后显示工具栏，维持其高于本次会话的所有覆盖窗口；隐藏于系统模态操作期间。
- 顶层窗口与按钮共同处理不激活策略，不把 WS_EX_NOACTIVATE 当作子按钮不会抢焦点的保证。现有 Enter、Ctrl+C、Ctrl+S、Esc 在点击工具栏后仍有效。
- 按钮保留原生可访问名称，悬停提示不作为唯一语义来源。
- CloseOverlay 先解除工具栏回调并销毁工具栏和提示窗，再关闭覆盖窗口和冻结帧；重复关闭安全。
- 工具栏仅参与显示，生成时间在冻结帧捕获之后，所有导出仍消费原有冻结帧，保存和复制不包含工具栏。
- 工具栏创建失败记录日志并显示本地化提示，保留原有快捷键截图能力；不把工具栏失败转成冻结图像或输出数据错误。

# 0.3.0 顶层窗口自动预选方案

状态：用户已批准施工，代码已接入；验证结果见实现进度。日期：2026-09-14。
首版目标：截图时悬停预选普通窗口，单击确认，拖动仍可自由框选。
依据：[产品需求第 8 节](../product_requirements.md)、[开发规范](../development.md)。

## 1. 已确认范围

用户本轮明确确认：

- 桌面空白处不显示预选框，只允许拖动框选，不自动选择整块屏幕。
- 必须先单击确认选区，Enter、Ctrl+C、Ctrl+S 才可复制或保存。
- 首版识别普通应用窗口、对话框和已有贴图；任务栏、右键菜单、工具提示不纳入。

进入截图默认启用窗口预选，首版不增加设置开关。UI Automation 子控件识别以后独立设计。
本轮不推进冻结指针、贴图层级优化、标注、安装版或检查更新；不重复已完成设置功能的人工检查。

## 2. 用户操作

| 状态／操作 | 首版行为 |
| --- | --- |
| 刚进入截图 | 按当前鼠标位置显示候选，不必先移动鼠标。候选内保持冻结帧原色，外部变暗，边框沿用选框颜色设置。 |
| 未确认，鼠标移动 | 预选鼠标所在位置最靠上的合格窗口；只显示边框，不显示八个控制点和工具栏。 |
| 桌面空白或不支持的系统区域 | 不显示候选，允许手动拖动。 |
| 在候选上按下后直接松开 | 确认按下时的窗口矩形，出现八个控制点和现有工具栏。 |
| 在候选上按下并拖动 | 超过拖动容差后，从最初按下位置创建自由矩形，不把窗口矩形当作拖动起点。 |
| 已有确认选区 | 移动、八点缩放和现有工具栏照常工作；悬停不再更换选区，选区外点击保持现有不重选行为。 |
| 只有候选时按 Enter／Ctrl+C／Ctrl+S | 不执行输出，也不把候选暗中转成正式选区。 |
| 只有候选时按 Esc／右键 | 直接退出截图，因为此时还没有正式选区。 |
| 正在按下待判定或拖动时取消 | 先取消当前操作；新建回到悬停预选，移动／缩放恢复操作前矩形。 |
| 已确认选区时取消 | 清除正式选区，按当前鼠标位置恢复候选；再次取消退出。 |

窗口矩形采用可见外框，包含标题栏，尽量排除不可见缩放边缘。跨屏窗口保留完整矩形，只裁掉虚拟桌面之外的部分。
选择部分被遮挡窗口时仍选择完整矩形，输出保留冻结画面中原有的遮挡物；不会提起窗口或补抓被遮住的内容。
这延续现有“所有输出只裁切同一份冻结桌面”的规则，不增加独立窗口捕获。

## 3. 现状与最小接入

- `App::StartCapture` 当前依次暂停贴图交互、捕获冻结帧、创建并绘制隐藏遮罩、显示遮罩。
- `SelectionModel::Begin` 在无选区时立即开始自由创建；零面积抬起清空，因此目前没有单击选窗口的入口。
- `App::OverlayProc` 管理按下／移动／抬起、失捕、取消、快捷键和重绘；完成命令已有稳定选区及代次校验。
- `OverlayRenderer` 已接受矩形、是否显示选区、是否显示控制点的绘制快照，可直接画候选外框和外部暗层。

生产范围拟限定为：

| 文件／模块 | 变动职责 |
| --- | --- |
| Application 新增 `private/window_selection_snapshot.h`、`source/window_selection_snapshot.cpp` | 采集一次窗口元数据、恢复 Z 序、分类和纯几何候选查询。 |
| Application 新增 `private/capture_selection_input.h`、`source/capture_selection_input.cpp` | 纯输入状态：锁定按下候选、判定单击／拖动、取消；系统参数由 App 注入。 |
| Application 新增 `source/app_selection.cpp` | 把窗口候选、输入状态和现有模型连接起来，形成统一绘制快照与鼠标处理入口。 |
| Application `include/app.h`、`source/app.cpp` | 持有会话状态，在开始／输入／绘制／结束时调用上述职责；不开展无关拆分。 |
| Graphics `include/selection_model.h`、`source/selection_model.cpp` | 增加显式采用候选矩形的入口，例如 `SelectRectangle`。 |
| 对应 CMake 和镜像测试 | 登记实际新增文件、Application 私有链接 `dwmapi`，补充有针对性的测试。 |
| 文档 | 获批施工后同步需求、架构、决策及进度。 |

不修改 Common/WindowRenderer、OverlayRenderer 绘制实现、Capture 捕获流程内部、Export 编码、PinWindow 排序。
新辅助类保持 Application 私有，不引入第三方库、后台轮询、跨模块反向依赖或空公共模块。

## 4. 窗口范围快照

### 时序和生命周期

1. 沿用现有截图准入和 `PinWindowManager::BeginCapture`。
2. 捕获并保留原 SDR/HDR 冻结帧。
3. 在创建任何截图遮罩、工具栏之前，读取一次窗口范围和层级，生成会话内只读记录。
4. 设置选区桌面边界，并用当前物理鼠标位置计算首次候选，再绘制隐藏遮罩首帧和显示。
5. 后续鼠标移动只查内存矩形，不调用目标窗口过程，不查询 UIA，不重新抓屏。
6. 会话结束或显示布局失效时，与候选、按下状态一起清理记录。

窗口枚举与冻结帧捕获没有系统级原子保证。目标在这段很短的间隔内移动时可能存在范围偏差；允许直接手动框选。
会话开始后即使原窗口移动、关闭或句柄被复用，也不再读取该 HWND，候选仍表示记录时的冻结桌面位置。

### 枚举与排序

采用 `EnumWindows` 收集顶层节点，先记录完整集合及各节点 `GW_HWNDPREV`，再在内存建立从上到下的链。
不把 `EnumWindows` 回调顺序当作正式 Z 序承诺；也不在鼠标移动时循环遍历实时 HWND。
隐藏／cloaked／不支持类型也先保留排序节点，候选过滤在排序完成之后执行。
系统偶尔枚举的非根窗口不参与顶层链；需显式识别，不能混入兄弟关系。

检查重复句柄、集合外前驱、自环／长环、分叉、多根及无法覆盖的节点；有异常时整次关闭自动预选，继续自由框选。
不循环重试，不通过猜测顺序发布部分候选。枚举记录和链遍历各限制最多 2048 个节点。
额外采集预算初拟 32 ms，在节点之间检查并主动中止；这是合作式预算，不宣称可以抢占单次系统调用或保证硬实时。
性能验收分别记录采集开销和现有截图耗时，若普通桌面频繁超预算则先调查，不以默认关闭功能掩盖问题。

一次只读设计核验：本机 `EnumWindows` 返回 399 个节点，未发现非根节点或集合外前驱，只有一个空前驱。
该样本支持本方案在当前桌面可形成完整链，不能代替施工后的跨环境验证。

微软明确指出 `EnumWindows` 较实时 `GetWindow` 循环可靠，并说明可能包含少数系统子窗口；
本方案的内存链校验用于处理非原子快照中的关系变化。[EnumWindows 官方说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumwindows)

### 类型与遮挡

- 隐藏、最小化、确认 cloaked、空矩形或完全在捕获桌面外的节点不提供候选。
- 普通窗口、独立对话框、自绘无边框应用可选；不因没有标题栏或 `WS_POPUP` 就排除。
- 已有贴图按其实际显示矩形参与。当前贴图是可激活的顶层工具窗口，没有 `WS_EX_NOACTIVATE`；
  分类不能排除整个本进程或所有 `WS_EX_TOOLWINDOW`，因此无需另建贴图 HWND 台账或扩展 PinWindow 接口。
- 已知桌面宿主、任务栏、标准菜单和工具提示按系统角色／类排除。其可见矩形保留为阻挡：命中它们时返回无候选，
  不穿透到下面的普通窗口。类名只用于这些明确排除的系统类别，不维护按应用名称或进程 PID 的支持白名单。
- 其他明显的非激活工具浮层保守作为阻挡；不能单凭 `WS_EX_TOOLWINDOW`、`WS_EX_TRANSPARENT` 一刀切排除普通应用。
- 不读取窗口标题、文档内容或其他应用控件，不向其发送 `WM_NCHITTEST`／`WM_GETTEXT` 或调用 `PrintWindow`。

首版按矩形识别，不承诺按半透明／异形窗口的每个像素穿透命中。完全自绘的菜单和提示可能没有可区分的系统类型，
不能承诺百分百识别；优先保守处理已知工具浮层，其他自绘内容仍按所属顶层窗口矩形处理，可手动调整选区。

### 几何与失败

- 所有记录统一为虚拟桌面物理像素半开矩形。鼠标只在实际捕获的输出区域内查询候选。
- 优先 `DWMWA_EXTENDED_FRAME_BOUNDS`；失败时仅在明确的 Per-Monitor V2 调用上下文使用 `GetWindowRect`。
  DWM 返回的框不再做第二次 DPI 缩放；后备框可能带不可见缩放边缘，应记录来源。
- 候选与冻结帧桌面外接矩形求交，不平移窗口来容纳它；要求与至少一块实际捕获输出相交。
  跨屏间隙的输出填充沿用当前裁切规则，不在本阶段修改图像合成。
- DWM cloaked 查询失败、可见节点矩形无法确认、句柄读取期间失效、排序不完整或预算耗尽时，
  本次不发布智能候选，继续自由框选。每会话最多记录一次粗粒度诊断，不弹错误窗口、不重复查询。

`GetWindowRect` 存在 DPI 虚拟化并可能包含不可见缩放边缘；微软建议用 DWM 属性取得可见边界。
[GetWindowRect 官方说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowrect)

## 5. 候选与正式选区分离

App 只在模型为 Unselected 且没有待判定按下时更新候选，保存值类型矩形，不把候选写入模型。
统一绘制快照生成函数优先返回正式模型快照；仅在无正式选区且存在候选时，构造 `hasSelection=true`、
`showHandles=false` 的绘制副本。该副本只给 OverlayRenderer，不给工具栏或输出准入使用。
候选矩形没有变化时不请求额外重绘；变化时沿用所有屏幕共享同一全局矩形的刷新方式。

`SelectionModel::SelectRectangle` 只在未选中且没有进行中操作时接受非空矩形；裁切到边界后为空则失败且不改状态。
成功后一次进入 Selected，生成八个控制点，并使旧命令代次失效后刷新工具栏。
不通过伪造 Begin／Update／End 拖动来采用窗口范围。

`CanSubmitToolbarCommand` 和完成函数继续要求正式 Selected，不增加“有候选就允许”的分支。
现有输入时间屏障、命令代次和单请求保护保留；切换候选不产生输出请求。

## 6. 单击与拖动

有候选的左键按下进入 PendingClick，记录按下位置、候选矩形和当时的拖动容差，获得鼠标捕获。
容差读取按下所在遮罩／显示器 DPI 对应的系统拖动尺寸，冻结到本次交互结束；不使用被选应用的 DPI 来决定容差。
纯输入助手只接受明确的物理像素容差，按起点周围的半开容差矩形判定，边界纳入测试。

- 容差内移动：仍显示锁定候选，不跟随鼠标切换窗口。
- 首次离开容差：永久切换为自由创建，清除候选，调用现有 Begin(原按下点) 后 Update(当前点)。
- 抬起也检查容差，覆盖鼠标消息合并、没有收到 MOVE 的情况；一旦进入拖动，即使回原点也不会转回窗口单击。
- 容差内抬起：采用锁定矩形；完成状态转换后才释放捕获，避免同步失捕消息误取消刚确认的选区。
- 没有候选的按下：立即沿用原自由框选，保持小范围手动框选能力。
- 已选区移动／缩放：完全沿用原模型，不加入新的拖动容差。
- Esc／右键、捕获失败、WM_CAPTURECHANGED、WM_CANCELMODE、会话关闭均先清空 PendingClick，再释放捕获或恢复候选。
  不能只检查 SelectionPhase::Dragging，否则会漏掉新待判定状态。

## 7. 施工拆分与验收

获批后由子 Agent 监督，按三步推进：

1. 私有快照分类／排序与纯输入判定、SelectionModel 显式矩形采用；先用可控数据验证边界。
2. 接入捕获会话、首次候选、输入和绘制副本，验证原手动选区及完成命令准入。
3. Debug /W4 /WX、Release、相关模块和全量回归；少量真实桌面用例验证窗口选择，不扩大为旧功能重新验收。

自动测试应包含：

- Z 序与重叠、隐藏／cloaked、最小化、普通无边框窗、独立对话框、贴图、桌面和不支持可见窗阻挡。
- 查询失败、重复节点、缺前驱、环、分叉、非根系统节点、预算终止，保证降级后自由框选仍可用。
- 负坐标、混合 DPI、跨屏矩形和间隙、桌面边界裁切、空矩形及源 HWND 在快照完成后销毁。
- 初始不动鼠标也有候选、候选阶段快捷键无输出、单击后快捷键与工具栏统一使用所选矩形。
- 按下后锁定候选、微动／阈值边界、只收到抬起、拖出后返回起点、捕获失败／丢失、取消及跨屏拖动。
- 清空正式选区恢复候选、再次取消退出，既有移动／缩放和选区外点击行为不变。
- 确认窗口范围后的复制／保存／贴图沿用同一冻结帧，真实输出边界通过模拟输出和已有裁切像素测试核对。

真实桌面测试用自有普通窗口制造重叠，独立检查被选矩形；设置串行约束及超时，全部自行回收，不移动其他应用窗口。
人工只需检查本功能的预选观感、点击／拖动区分，以及当前机器可用的跨屏环境；不将自动几何通过写成视觉已验收。
历史零冗余贴图测试可能继续失败，按 D-066 单列；不能在本阶段顺带修改 PinWindow 来消除它。

## 8. 设计复核

子 Agent 已独立核对需求、App 输入／捕获、SelectionModel 和 OverlayRenderer，认可上述最小职责范围。
本稿纳入候选与正式选区隔离、抬起阈值、失捕回退、可见不支持窗阻挡、快照不闭合降级及已有贴图例外。
设计阶段仅新增方案文档；随后用户明确批准施工，已按本稿范围接入产品与测试。
实际验证结果和保留的边界见 [实现进度](../implementation_progress.md)。

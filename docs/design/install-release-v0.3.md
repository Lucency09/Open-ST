# Windows 安装与发布方案

日期：2026-09-18。状态：用户已批准完整方案，正在施工与验证。
用户已确定首版同时提供当前用户安装、所有用户安装及 ZIP 便携版；跨进程共享文件锁被占用时立即报错，不等待、不自动重试。
依据：[实现进度](../implementation_progress.md)、[开发规范](../development.md)、[产品需求](../product_requirements.md)、决策 D-074。

## 1. 首版范围

- 一个 Windows x64 Setup，安装时选择当前用户或所有用户，均支持自定义本地目录；另保留 ZIP。
- 安装、同范围原路径升级、卸载、快捷方式、卸载登记、运行库检查，以及版本化发行产物。
- 可写数据仍为 EXE 旁 `data/`，日志仍为 `data/logs/`；同安装目录跨 Windows 用户共享，不另建按用户分离的数据目录。
- 补齐共享数据并发协调，保持现有每 Windows 用户单实例，不改成整台机器只能运行一个实例。
- 关于窗口提供检查更新：查询后先确认；安装版确认后自动下载并打开 Setup，便携版确认后打开对应发布页，具体见 5.4。首版不包含静默安装、后台定时检查、后台服务、OCR、翻译或新的 CI 平台；公开 GitHub Release 另经确认。
- 不支持原地切换安装范围、覆盖接管旧 ZIP 目录、版本降级或未经验证的网络路径安装。

## 2. 现状与实际缺口

| 需求 | 已有能力 | 本轮补充 |
|---|---|---|
| Release 构建 | `scripts/build.ps1` 已整理 EXE、DLL、resources 和许可；`-Package` 复制版本化目录 | 复用整理逻辑，生成同源 Setup、ZIP 和校验文件，排除运行数据 |
| 版本 | CMake `PROJECT_VERSION` 生成版本头 | 去掉打包路径硬编码；补 EXE VERSIONINFO；校验 vcpkg 版本一致 |
| 设置持久化 | Common JSON 的缓存、进程内锁、编辑回调和原子替换 | 将跨进程锁覆盖整个读取最新值到提交的事务 |
| 日志 | Common Logger 已有续写、轮转、维护及退出清理 | 活跃文件独占与跨进程清理协调，避免两进程续写同一文件 |
| 单实例、自启 | SystemIntegration 按用户 SID 单实例，HKCU 启动项识别和修复 | 安装目录维护保护；卸载不能误用会删除 OtherPath 的 `Apply(false)` |
| 错误窗口 | WindowRenderer 和 App 现有提示入口 | 复用提示及本地化，Common 不创建窗口 |
| 安装 UI | 暂无安装器 | 使用 Inno Setup 标准安装／卸载界面，不在 App 自制安装窗口 |
| 获取新版 | 已有编译版本、关于提示及公共窗口；Settings 已有默认 JSON 查询 | Update 查询／下载安装包；关于窗口复用 Renderer 查询与确认，Settings JSON 标记发行模式 |

当前源码证据：`json_file.cpp` 的 `Write(editor)` 只有进程内 mutex；`logger.cpp` 的 `OpenLatestLocked` 会选择当天最后一个文件；
`single_instance.cpp` 的实例身份含用户 SID；`startup_registration.cpp` 的关闭操作允许移除同名其他路径登记。
因此“给最终写文件的一行加锁”不足以完整覆盖读改写及日志寿命，但可在现有模块内补齐，不重建文件系统框架。

## 3. 安装范围、目录和权限

| 项目 | 当前用户 | 所有用户 |
|---|---|---|
| 建议默认目录 | `%USERPROFILE%\Applications\Open-ST` | `%ProgramFiles%\Open-ST` |
| 自定义路径 | 允许当前账户可写的本地专用目录 | 允许本地专用目录，按所有用户权限配置 |
| 安装权限 | 通常不提权；目标不可写则提示重新选目录 | 请求管理员权限，拒绝时不继续 |
| 快捷方式和卸载登记 | 当前用户 | 所有用户 |
| 运行数据 | `{安装目录}\data` | `{安装目录}\data`，同目录共享 |
| 主程序运行权限 | 普通用户 | 普通用户，不要求管理员运行 |

自定义路径不会取消安装范围的差别；是否会并发写同一数据，取决于实际使用的目录，不由安装范围自动保证。
所有用户模式只对 `data/` 授予 Users 修改及继承权限，不对 EXE、DLL、resources 或整个安装根目录授予写权限。
自定义目录还须检查既有 ACL：若普通用户已经可以修改程序文件，应修正本应用专用目录权限或拒绝该目标，不能仅做到“不额外授予”。
安装后核验数据目录有效权限，权限设置失败不能静默报告安装成功。拒绝把盘符根、系统根、现有无归属目录当安装目标。
默认目录不使用 AppData，以继续遵守现有约束；用户自定义目录中的数据也始终跟随 EXE，不另做隐式重定向。

建议使用 Inno Setup 的 `PrivilegesRequired` 与 `PrivilegesRequiredOverridesAllowed=dialog` 提供范围选择。
同一产品使用固定 AppId，版本号不进入安装身份；已有登记的升级固定原范围和路径。

## 4. 文件锁与报错规则

### 4.1 共用原语

Common 提供最小的 RAII 文件租约原语：调用方提供稳定锁文件路径、共享／独占模式，内部使用 Win32 `LockFileEx` 的立即失败模式。
只做一次获取尝试，不睡眠、不轮询、不定时重试。区分 Busy、权限不足、普通 I/O 错误；关闭句柄时释放锁，进程异常退出由系统回收。
锁文件存在不代表被占用，不能凭文件存在或 PID 文本判断、删除“陈旧锁”。锁路径须能被访问同份数据的用户共同访问。
该规则针对跨进程文件协调；不改写现有短时线程内互斥契约，也不让 Common 依赖 App 或 WindowRenderer。

Common 的 JSON 和 Logger 内部复用这一原语。SystemIntegration 的安装目录保护是第二个真实消费者，因此原语可提供窄公共接口；
Common 不内置 Open-ST 安装目录、设置键、安装范围或窗口行为。

### 4.2 JSON 事务

- 写入使用稳定 sidecar 锁文件，不能把会被原子替换的 JSON 文件句柄自身当作稳定锁身份。
- 保留进程内锁；取得跨进程独占锁后才读取磁盘最新版本，执行原有编辑／冲突校验、临时写入及原子提交，提交结束后释放。
- `Write(document)` 和 `Write(editor)` 共用该边界；完整替换与回调条件提交保留各自语义，不以锁替代业务冲突校验。
- 获锁失败立即返回 Busy，不写磁盘、不发布候选缓存；Settings 保留用户草稿，通过既有窗口提示稍后手动重试。
- 保持 `IsValid/Read/Write` 入口；可增加可选错误输出承载 Busy，不新增第二套 JSON 管理器或通用业务事务引擎。
- 原有读取、签名检查和缓存失败语义保留。只读 `resources/*.json` 不创建旁路锁文件，不因安装到 Program Files 而要求修改资源目录权限。
- Settings 继续负责字段冲突和保存后的当前进程副作用；另一用户修改共享设置，不意味着自动改变所有其他会话已注册的快捷键或 HKCU 自启。

### 4.3 日志

- 每个进程独占自己的活跃文件。当天旧日志只有确认不被占用后才能续写；同时启动的进程不能共写一个文件。
- 新日志沿用时间戳与碰撞序号格式，创建使用原子排他方式；启动和轮转的共享目录协调仍只尝试一次。
- 普通日志行写入自有文件，不给每一行增加跨用户全局互斥；日志并发规则不放进 App。
- 常规轮转、维护清理和退出清理共用活跃文件保护，活跃文件始终不属于删除目标；结果注明正常保留数量。
- “正常保留活跃文件”与“本次操作协调锁 Busy”分开：前者不等待也不重试；后者终止本次操作并上报占用错误。
- 若清理中途遇到占用或其他失败，保留真实已完成数量，不报告全部成功。保留上限不能靠删除其他进程的活跃日志达成。
- Busy 不进入旧的自动清理重试链；用户显式再次清理属于新操作。普通 I/O 故障原有手动重试入口保留。

### 4.4 窗口归属

用户点击保存／清理遇到 Busy，立即显示“文件正被其他进程使用，本次操作未完成，请稍后重试”等本地化错误。
Common 只给错误结果；Settings 使用已有 Renderer，App 使用既有提示编排。安装器使用自己的标准错误窗口。
后台日志错误通过窄通知交给 UI 线程，在最早安全消息边界提示；同一故障去重，不能每条日志弹窗或为记录锁错误递归写日志。
不在锁内、工作线程或截图鼠标捕获回调中启动模态循环。“安全消息边界”用于避免重入，不是等待文件锁释放。

## 5. 安装、升级与卸载

### 5.1 安装期间的运行保护

SystemIntegration 封装安装目录运行租约：正常程序共享持有 `data/.coordination/install.lock` 的约定字节；
安装／升级／卸载在同一文件和字节上独占持有。多个用户正常运行可共存，维护与运行互斥。
App 只负责获取／释放时序；任何资源 JSON、设置或日志初始化前取得租约，退出清理结束后才释放。
现有第二实例启动也会读取语言资源，必须让这段读取受短租约保护或调整到安全的转发流程，不能只保护主实例。

安装器通过同一 Win32 文件锁协议协调，只有极小的系统 API 适配，不另写设置或日志管理。
租约独占失败立即提示并终止本次操作；程序在维护期间启动也立即报错退出，不等待、不抢占或强杀其他用户进程。
安装器同时保留自身并发运行保护，不能仅在安装开始枚举一次进程就宣称消除了竞争。
锁文件在操作结束前不能删除重建；显式清理数据时最后处理协调目录，并确保 EXE 已不可启动。
提升权限的安装器在共享 data 内创建／打开锁文件、写入升级备份时，同样校验路径归属并拒绝重解析点绕出目标目录，不只在删除时检查。

### 5.2 安装和升级

- 开始菜单快捷方式默认创建，桌面快捷方式可选；安装结束启动程序可选，必须回到原用户普通权限执行。
- 安装器不设置开机启动；继续由程序现有首次欢迎／设置处理，不引入 HKLM 全员自启。
- 新安装只接受新目录或确属本产品的受管理目录；已有 ZIP 先退出，安装到新目录后再显式迁移 `data/`，不自动接管。
- 同版本允许修复安装；升级按数值版本比较，拒绝降级及原地更换安装范围。版本依据受管理登记和程序版本，不信任用户数据中的版本字段。
- 升级只覆盖发行清单中的程序、依赖、资源及许可；默认不覆盖设置、日志或其他用户数据。
- 官方资源按新版本更新。若现有资源与原版清单哈希不一致，先备份到 `data/upgrade-backups/<版本与时间>/` 并告知用户；不自动合并 JSON 或将旧文件直接恢复到新版本。
- 旧版废弃文件仅按受管理清单删除，保留未知文件；备份是升级通常不写 data 的明确例外。
- 路径、占用、运行库等前置检查失败时不替换应用文件。开始复制后的失败使用安装器可验证的恢复能力并报告实际状态，不承诺断电下的完整版本事务。

### 5.3 卸载与副本共存

- 默认只卸载该安装登记拥有的文件、快捷方式和卸载项，保留 `data/`；额外提供默认选择“不删除”的数据删除确认。
- 安装器仅在文件校验成功后，在范围匹配的 HKCU／HKLM 专用 InstallationReceipts 键发布 AppId、规范路径、范围、版本及 complete 状态。路径键使用 Unicode SHA-256，不读取用户 Settings 作为归属证明。
- 卸载保留数据时保留此归属记录，以支持同目录重装；重装须匹配该记录、版本不降级、目录只剩安全 data，不接管旧 ZIP 或未知目录。明确删除数据成功后才移除精确匹配的本路径记录。该记录属于安装器元数据，App 不消费。
- 所有删除都校验最终路径及归属，不跟随重解析点跳出安装目录；不递归清空带未知文件的整个安装根目录。
- 当前用户卸载只删除完整命令精确匹配本安装路径的 HKCU 自启值；不按进程名或 EXE 文件名删除其他副本登记，不直接调用现有 `Apply(false)`。
- 所有用户安装的管理员卸载不把提升后的 HKCU 当作原用户，也不加载或遍历删除其他账户的离线注册表配置。
  首版明确提示：各用户曾在程序内启用的自启须在卸载前自行关闭，其他账户的路径登记可能残留；不能宣称跨账户自启已全部清理。
- 安装版和 ZIP 可以放在不同目录，但保留既有同一 Windows 用户单实例语义，不承诺同用户多副本同时运行。
- 程序数据不自动迁移或跨目录共享；不同用户确实运行同一目录时，使用第 4 节的数据协调。

### 5.4 关于窗口中的检查更新

按用户最新修订，检查更新统一位于“关于”窗口；先查询和确认，再按发行模式执行。此前“托盘直接检查、两种模式都只开网页”的建议由本节替代。

#### 5.4.1 复用现有窗口和 Settings JSON

- 关于窗口显示当前版本与“检查更新”按钮，复用 Common/WindowRenderer 的 LoadLayout、BindAction、ShowModal、RefreshValue、SetStatus 和现有线程消息转发机制。
- 已是最新、失败等普通提示复用现有简单提示能力；新版确认使用公共 Renderer 的标准按钮和模态能力，业务适配仅提供版本、文字和确认／取消结果，不复制原生控件、字体、DPI 或消息循环。
- 关于窗口自身的模态期间也须能消费查询／下载完成通知，不能被 App 的普通模态准入挡住；回调只投递意图，安全边界打开确认窗或安装器。
- 发行模式写在 Settings 已有资源 `resources/default_settings.json` 的 `settings` 对象内：`"distribution.mode": "installed"` 或 `"portable"`。
- 直接复用 `GetDefaultStringSetting("distribution.mode")` → Settings 已持有的默认 JSON 句柄 → Common Read，不新增配置管理器，不让 Update 直接读 JSON 文件。
- 该字段是打包元数据，不是可编辑的用户偏好：初始化 data/settings.json 时不复制它；已有用户文件中的同名残留也不覆盖资源值。恢复用户默认设置不改变发行模式。
- App 只将校验过的模式传给 Update。缺失或非法值明确提示发行配置异常，不按目录名、管理员权限或注册表猜测；更新操作停止，其他功能仍按原准入工作。
- Setup 和 ZIP 由同一个基础 staging 派生两个产物视图，只在各自默认设置资源内写入不同模式，再分别生成资源清单／哈希；不修改仓库源 JSON，不轮流污染同一 staging。
- 模式只决定更新交互，不证明安装登记有效；安装器仍独立核验安装身份、范围和目录。复制整个安装目录会连同模式一起复制，不能据此承诺新位置可直接覆盖升级。

#### 5.4.2 用户流程

1. 点击“检查更新”，异步请求 `GET https://api.github.com/repos/Lucency09/Open-ST/releases/latest`，关于窗口显示检查状态；重复点击不创建并行任务。
2. 校验正式 Release 的 draft／prerelease 标志、`tag_name`、页面和资产。版本接受可选小写 v 加 major.minor.patch，按三段数值比较，拒绝溢出和额外后缀。
3. **当前与线上一致**：弹“当前已是最新版本”，不下载。**本地领先**：提示当前版本高于线上正式版，不降级。404 提示“未找到可用正式发行版”；网络或限流等错误单独提示，不冒充已最新。
4. **发现新版**：弹确认窗口，显示当前版本和新版本。取消或关闭不下载、不打开网页；确认针对这次查到的固定 Release，不在确认后静默换成另一版。
5. **安装版**：确认文字明确“下载新版安装包并打开安装程序”。点击确认后，自动下载该版本 `Open-ST-<版本>-win-x64-Setup.exe`，显示进度并允许取消；完整性校验成功后自动打开 Setup，不再要求用户手动寻找文件或再次点击下载。
6. **便携版**：确认文字明确“打开新版发布页，自行下载 ZIP”。确认后打开该具体版本的本仓库 HTTPS Release 页面；由用户退出旧程序、备份 data、自行下载解压并覆盖程序及资源，保留 data。不能把 GitHub 自动生成的源码 ZIP 当可运行包。
7. 安装版缺 Setup 或可用校验值时提示“安装包尚未就绪”，不得改下未知 EXE、跳过校验或悄悄走便携分支；便携版缺 ZIP 同样说明发行包不完整。

程序不后台定时检查，不在用户确认之前下载。首版的“打开 Setup”不是静默完成升级，不在应用内自替换程序文件。

#### 5.4.3 下载、校验和文件寿命

- 使用 WinHTTP、系统代理和 TLS 校验；不硬编码开发机代理、不内置 GitHub Token 或任意镜像。
- 元数据查询维持 10 秒总截止时间、1 MiB 响应上限。Setup 下载单独设置总时限 10 分钟、无进展时限 30 秒、体积上限 512 MiB；与 API 声明的长度一致，超限或超时立即失败，不自动重试。
- 固定本次 release ID、tag、asset ID、名称、长度和 SHA-256；优先使用 GitHub 资产的 sha256 digest，缺失时读取同一 Release 的 SHA256SUMS 并要求唯一精确匹配记录。两者同时存在须一致，下载后按实际字节核对。
- GitHub 资产二进制接口允许直接返回内容或跳转到资产 CDN；每跳只接受经核验的 GitHub 资产 HTTPS 域名，限定跳数，拒绝降级、外站和异常 URL。页面也只接受精确的本仓库 release/tag 路径。
- 元数据、校验清单、安装包下载分别检查状态和实际长度。只有完整文件通过校验后才可进入可启动状态；网络响应不能直接作为 Shell 命令执行。
- 缓存位于 EXE 旁 `data/updates/` 的独立请求目录，下载中使用不可执行的 .part，文件名由程序生成，不直接使用响应字符串拼接本地路径。
- 同目录可跨用户共享，缓存必须同时实施当前用户私有访问权限、拒绝重解析点、目录／文件句柄保护：持有从已解析路径到已验证文件的必要句柄，禁止校验后被改写、改名或路径替换，直至系统启动交接完成。仅给最下层目录设 ACL 不视为充分保护。
- SHA-256 用于核对 HTTPS 元数据对应的包内容，不等于 Authenticode 发布者签名。若发行已启用代码签名，还须验证预期发布者；未签名候选必须如实说明，不能声称已认证发布者。
- 取消或失败不启动；仅清理本请求持有的临时文件。已成功启动的 Setup 缓存不因关于窗口关闭或 App 退出而立即删除，下一次显式更新操作再清理可确认无占用的旧请求文件，不后台轮询。
- 系统拒绝启动或用户取消 UAC 时，报告实际结果，不宣称升级完成；允许用户重新发起。迟到完成回调不能绕过取消或关闭意图再次启动。

#### 5.4.4 与安装器及当前程序的衔接

下载完成后先打开标准 Setup，不强制关闭当前 Open-ST，也不丢弃用户正在展示的贴图。确认窗口说明安装前需要从托盘退出程序。
安装器成功启动并完成文件保留交接后，自动关闭“关于”窗口，解除其模态托盘门禁，让用户可以正常从托盘退出；启动失败则保留关于窗口供重试。不能在系统启动回调内部提前关闭，避免中断文件交接。
安装器在用户确认实际安装、完成目录／范围选择后才尝试独占维护租约，而不是一启动 Setup 就因当前程序仍运行而退出。
若届时当前用户或其他用户仍占用目录，立即弹占用错误，不等待、不强杀；用户退出相关实例后手动重新发起安装步骤。
此流程不新增独立 update.exe、进程退出等待协议或后台更新服务，安装覆盖仍复用第 5.2 节。

Update 拥有查询、确认后下载、校验、缓存保护及可取消任务状态；App 提交明确确认意图、协调关于窗口和系统启动。
关闭关于窗口取消尚未交接的任务，退出应用取消并有界回收；下载完成只传回受保护的本地文件，不在网络回调中启动安装器。
SystemIntegration 提供窄系统启动边界，接收由 App 适配的本地路径并报告启动结果，不依赖兄弟 Update 的具体类型。

## 6. 运行库、版本和发行产物

建议 Setup 附带经过版本、SHA-256 和微软签名核验的官方 VC++ x64 Redistributable，构建工具依赖固定版本并记录来源。
仅缺失或版本低于本次构建要求时，向用户说明并征得同意后执行；可能单独触发 UAC，拒绝或失败则停止后续安装。
已安装兼容新版本不降级；处理取消、失败和要求重启的结果，不把安装程序退出简单等同于应用可运行。
ZIP 继续说明运行库要求并提供微软官方下载链接。主程序保持普通权限；不静默安装编译器或 vcpkg。

版本以 CMake `PROJECT_VERSION` 为权威，生成应用版本头、EXE VERSIONINFO 和发行元数据；vcpkg 中的项目版本只做一致性校验。
复用现有 Release 整理过程，建立唯一发行清单；`build.ps1` 的打包选项、内部打包辅助与 Inno 文件列表都消费同一来源。
不从已经运行过的 `build/Release` 任意递归打包；只收录清单内 EXE、实际依赖 DLL、resources、许可和发行说明。
拒绝混入 `data/`、日志、截图、API Key、PDB、测试工具或缓存。构建工具定位采用明确参数或 vswhere，去掉发行路径中的开发机盘符假设。

建议输出：

- `Open-ST-<版本>-win-x64-Setup.exe`
- `Open-ST-<版本>-win-x64.zip`
- `SHA256SUMS.txt`
- 发行说明及内部构建记录：提交号、编译／安装工具版本、运行库版本、功能开关和文件清单。

不在此设计阶段递增版本或对外发布。安装器工具及运行库版本在施工时核验并固定，不使用不可追踪的“最新”下载结果。
签名凭据不入库；没有签名条件时可生成明确标注的未签名候选包，正式对外发布的签名选择单独确认，不承诺免除系统信誉提示。

### 6.1 构建脚本选项

用户要求在现有构建脚本中直接选择构建安装包。对外保留单一入口 `scripts/build.ps1`，拟新增 `-Installer`：

```powershell
# 只构建 Release 运行目录，保持现有行为。
.\scripts\build.ps1 -Configuration Release

# 保留版本化目录，并生成 ZIP 便携包和校验文件。
.\scripts\build.ps1 -Configuration Release -Package

# 构建 Setup 安装包和校验文件，不强制生成 ZIP。
.\scripts\build.ps1 -Configuration Release -Installer

# 一次构建，同时生成 Setup、ZIP 和统一校验文件。
.\scripts\build.ps1 -Configuration Release -Package -Installer
```

- `-Installer` 和 `-Package` 均只接受 Release；Debug 组合直接报参数错误。`-Clean` 仍仅清理后退出，不继续打包。
- 两个选项同时启用只编译一次，从同一基础 staging 派生 Setup／ZIP 视图并分别设置 distribution.mode、计算资源哈希；共用版本和文件清单来源。保留既有 `-Package` 的版本化目录，增加 ZIP 输出。
- 可用 `-InnoSetupCompiler <ISCC.exe路径>` 指定已安装编译器，未指定时按约定发现并核验版本；缺工具明确报错，不自动安装。
- 使用内部共用打包辅助收拢文件清单和归档逻辑，不额外建立必须单独使用的公开打包脚本，不重复维护 CMake／PowerShell／Inno 的文件名单。
- 生成 Setup 前核验其所需 VC++ Redistributable 输入和版本／签名；未准备好时提示缺口并退出，不在普通构建中隐式下载未知版本。单独 `-Package` 生成 ZIP 不要求准备该运行库安装程序。
- 输出仅进入本次版本目录；本次请求任一产物失败，命令返回失败，并明确已生成哪些产物，不能把旧安装包当成新构建成功。
- `SHA256SUMS.txt` 覆盖本次完整成功的目标产物，先在临时目录准备，再发布到产物目录；不把散落的历史文件纳入本次校验。

构建选项已接入；实现与验证状态以实现进度为准。

### 6.2 发布端如何让客户端找到新版

在确认发布后，按以下流程准备 GitHub 正式 Release：

1. 从已确认的提交构建发行包，核对程序／安装器／文件名版本以及目标 tag 一致，附准确的发行说明。
2. 先创建草稿，上传 Setup、ZIP 和 SHA256SUMS；核对资产名称、大小及上传内容与本地产物哈希一致。
3. 资产齐全并完成发行验收后，发布为非预发布的正式 Release，明确设置 Latest；失败时保持草稿，不让客户端发现缺包版本。
4. 发布后读取同一 `/releases/latest` 接口，验证返回 tag、页面和资产符合本次发布预期。该检查不能代替正式发布授权。

本节只规定流程，不在设计阶段创建 tag、上传包或公开发布，也不因此增加自动 CI 发布。

## 8. 施工顺序及验收

1. **共享数据基础**：Common 文件租约、JSON 跨进程事务、Logger 活跃文件与 Busy 上报；接入既有业务错误窗口。
   验证两进程同时改不同字段不会丢更新、同字段冲突保持草稿、Busy 立即返回、持锁崩溃后可恢复、日志互不共写且活跃文件不被清理。
2. **维护与版本打包**：SystemIntegration 租约和启动顺序；唯一版本／发行清单、VERSIONINFO、Setup 和 ZIP 的共同 staging。
   验证运行期间维护立即拒绝、维护期间新启动立即拒绝、不同目录不串锁、旧副本不被关闭或接管。
3. **安装器与升级卸载**：两种范围、自定义目录、权限、运行库提示、备份、升级与卸载。
   在隔离环境测试普通账户／管理员／替代管理员凭据、两个账户同时登录、缺运行库、中文与空格路径、数据保留、资源修改、占用及失败恢复。
4. **关于窗口更新闭环**：复用默认 Settings 模式读取、版本比较、公共确认窗口、WinHTTP 下载和系统启动边界。
   覆盖 0.9.0→0.10.0、同版／本地领先、非法标签／模式、旧 data 不覆盖模式、确认前零下载、取消、两种发行分流、404／限流／超时／缺包、CDN 跳转、哈希／长度错误、文件替换、下载期间关闭、启动失败及迟到回调；再核验真实联网和代理。
5. **发行准备**：Debug／Release 和相应回归；从干净状态检查 ZIP、Setup、SHA-256、许可和发行说明。
   Windows 10 22H2／Windows 11 x64 各完成安装、启动、升级、卸载验收；没有相应环境时如实保留未验收状态。
   验证 `-Installer` 单独／与 `-Package` 组合、两种包的模式不串写、Debug 拒绝、工具缺失、失败退出码、包内无 data，以及构建不隐式公开发布。

每步复核模块职责、生产复用、错误传播和旧实现清理。D-066 等已知后置问题单列，不以修改断言凑全绿；不将本机验收扩写成所有平台已通过。
获得完整方案批准后，先同步产品需求中“不提供安装器”和“不执行版本检查”等范围条款、共享日志清理规则及开发规范，再逐步施工。

# 0.3.0 日志与维护设置设计

状态：用户于 2026-09-13 明确批准整体方案，代码与自动验证完成；剩余人工验收见末节。
日期：2026-09-13。对应实现进度第 6 步。冻结鼠标指针继续后置。

## 1. 用户已确认的行为

- 恢复默认包含所有现有可设置项，包括界面语言和开机自启。
- 清理日志只删除历史日志，保留当前正在写入的日志，不停止日志服务、不切换新文件。
- 恢复默认经确认后立即保存并生效，不只修改草稿等待再点应用。

本轮功能为打开日志目录、清理历史日志、恢复全部可设置项默认值。
不删除截图、不处理历史图片、不增加日志级别/保留数量设置，不重置首次欢迎状态，也不修改后置指针功能。

## 2. 核对到的现状

- 日志位于 EXE 旁 data/logs；Logger 同步写入并由内部 mutex 串行保护，按行数/大小轮转，默认保留三份日志。
- ShutdownAndClearLogging 用于退出：先关闭日志，成功后还会清空目录状态，不能用作本轮运行中清理。
- OpenNewLocked 经 OpenPathLocked 会先关闭旧流；本轮保留当前文件，因此不需要调用这条路径。
- 退出清理已有本程序日志命名识别、逐级目录句柄和重解析点检查，可提取私有助手复用，不能降低保护。
- Settings 已有六项可设置字段、私有草稿、默认读取、条件批量提交与失败重试。
  原“恢复本页默认”仅改草稿；新“恢复全部设置”是单独明确标注的立即操作。
- Renderer 已有 button/text/row 等所需控件，本轮无需增加其功能或公共接口。

## 3. 页面

新增“维护”页，采用已有布局和本地化文字：

| 操作 | 说明及结果 |
| --- | --- |
| 打开日志目录 | 在资源管理器打开当前日志目录。不存在或不可用时说明原因，不打开替代路径。 |
| 清理历史日志 | 先确认，只清理本程序识别的历史日志，保留当前文件；显示进行中及完成/部分失败状态。 |
| 恢复全部设置 | 先列明恢复范围和影响，确认后立即批量保存并应用；完成后窗口保持打开。 |

维护页说明清理后当前日志仍存在，这是用户选择的正常结果，不以“目录变空”为成功条件。
恢复全部与清理日志互不绑定。打开目录和清理历史不应用、不覆盖其他页面尚未保存的草稿。
即使草稿暂时无效，这两个日志操作仍可使用；恢复全部也可替换无效草稿，但必须有可靠用户文件基线。

底部既有应用/确定/取消保留原行为；“恢复本页默认”在没有可恢复字段的维护页禁用，避免与立即恢复全部混淆。
已有常规、快捷键、截图与存储页的恢复本页行为不改变。

## 4. 打开日志目录

- Common 通过窄只读接口返回实际日志目录；不公开 Logger、LogOptions、当前文件流或测试目录注入。
- Application 校验目录有效后，通过系统固定 open 操作打开文件夹，不拼接可执行命令字符串，不等待资源管理器退出。
- 目录不存在时提示并允许重试，本操作不创建文件、不初始化或重启日志服务。
- Settings 通过 App 回调请求操作，不自行推测 EXE 路径或读取 Logger 私有状态。

## 5. 清理历史日志

### 范围和安全边界

- 只枚举配置日志目录的直接子项，沿用现有 Open-ST 日志命名识别规则，不按泛化的 *.log 删除。
- 本次清理不主动删除操作开始时的当前文件；删除每个候选前，在 Logger 锁内再次排除当时正在写入的文件。
  清理期间发生正常轮转时，新当前文件同样保留，开始时保留的文件也不转为本次删除目标。
  这不改变正常轮转及其既有历史保留策略，不承诺旧文件永远保留。
- 保留未知文件、子目录、非本程序命名文件；拒绝跟随目录或候选文件的符号链接/重解析点，不递归删除。
- 复用逐级目录句柄锚定与基于已打开文件句柄的删除，防止验证路径后换目标；无法证明目标安全时保留并报告。
- 当前文件保护不只依赖枚举时判断；如涉及文件别名，必要时检查身份，不能证明非当前文件就不删除。
- 候选已经被正常轮转清理时视为不再需要清理；权限/占用/枚举错误保留结果，不能一概算成功。

### 日志服务行为

Common 新增独立 ClearHistoricalLogs 入口，不调用 Shutdown、ShutdownAndClear、Initialize 或 OpenNew。
当前输出流、路径、计数、日期、初始化状态保持原有生命周期；清理失败也继续向当前日志写入。
候选枚举与删除允许取消检查；枚举不长时间持有日志写锁，每个实际删除在短临界区重新确认当前文件。
日志写入仍采用原同步机制，不能在锁内调用日志宏、本地化或 UI 以免重入。
正常轮转与清理的竞争通过候选消失检查和当前文件保护处理，不保证目录在并发轮转期间保持固定文件数。

返回结构化结果：完成、部分失败、无法开始或已取消，以及本次删除/失败等必要计数。
不向 UI 暴露所有历史文件名或低层异常文本。异常不越过日志模块边界。
操作不具备删除回滚；发生部分失败或取消时，明确已经成功删除的历史日志不会恢复。

### 后台执行和退出

- Application 拥有一个专用于此操作的 worker 和操作编号，不建设通用任务调度框架。
- 确认期间使用现有模态/忙状态；确认后历史清理在 worker 执行，设置窗口继续响应。
  同一时间只允许一个清理任务；截图和正常日志写入无需为整个清理周期暂停。
- 后台不调用 Settings 或本地化，也不捕获 Settings 指针、原始窗口句柄或已关闭页面的回调。
- 结果先存入 App 拥有的完成状态，再向稳定消息窗口发送通知；消息只携带操作编号，不传裸结果指针。
  通知失败时，后续主循环消息或设置窗口再次激活仍可收取完成状态，不能重复删除或永远保留独立的 busy 标志。
- 设置窗口关闭不取消已确认清理，重新打开可看到状态；UI 刷新不改变其他草稿。
- 程序退出或“退出并清理”启动时先请求停止选择新候选，并等待 worker 回收，再关闭日志或执行原退出清理。
  枚举和删除循环都检查取消；已经进入的文件系统调用需返回后才能结束，不承诺强制中断系统 IO，也不强杀线程。
- 清理完成后可记录一条不含文件正文的结果日志，写入仍是原当前文件。

## 6. 恢复全部默认设置

### 明确范围

| 字段 | 当前默认 |
| --- | --- |
| ui.language | en-US |
| startup.enabled | true |
| capture.hotkey | Ctrl+Alt+Q |
| capture.selection_border_color | #000000 |
| export.default_format | jpeg |
| export.jpeg_quality | 95 |

默认值实际从 default_settings.json 读取，不在恢复逻辑维护另一套默认常量。
onboarding.completed、capture.last_save_directory、未知/尚未提供设置界面的字段、日志、资源和图片均保留。
“全部”指当前六项已实现的可设置项；今后新增设置时再按对应业务方案扩展，不扫描整个默认 JSON 无差别覆盖用户文件。

### 确认流程

1. 准备独立默认候选，检查六项默认类型及业务合法性，保留当前编辑基线和原始草稿。
2. 确认窗口展示本次将采用的默认值，突出语言切换和自启状态；当前资源下为英文、开启自启。
   同时明确本次立即生效、会替换未应用的可设置项草稿；不清理日志或重新显示首次欢迎。
3. 取消则完全保留原草稿和运行状态。
4. 确认后使用刚才展示的固定默认候选，不在确认后静默换成另一份外部修改过的默认资源。
   必要的语言可用性与保存条件仍在提交前复核，失效就返回错误。

### 保存和系统生效

- 复用 Settings 私有编辑会话，以六项全部作为显式条件提交字段；即使数值本来等于默认，也要核验外部同键变化。
- 默认读取、验证、用户文件读取或同键冲突失败时不提交任何字段，保留原始草稿供用户修正/重新加载。
  用户文件损坏时不通过删除或整体重建来实现恢复。
- 默认快捷键先准备可用注册；被占用或准备失败时整批不保存，旧快捷键继续生效。
- 一次条件提交成功后无异常激活快捷键，并将编辑基线及草稿更新为已经保存的默认状态；随后复核并应用语言和当前用户自启入口。
  不能在文件已保存后，因某个系统副作用失败而继续展示未保存的旧草稿。
- 不能只根据 IsDirty 判定已经完成：配置虽已默认，但运行语言、快捷键注册或自启入口仍不一致时，也需要核验并执行相应应用。
- 自启沿用现有归属判断及安全应用入口，不覆盖无法确认属于 Open-ST 的注册内容，也不修改系统任务管理器禁用策略。
  确认说明应用的是当前程序的启动入口，不将写入 Run 值等同于操作系统一定会允许启动。
- 文件写入失败不触发语言/自启应用；文件已保存但语言或自启失败时，显示“默认配置已保存，部分设置未生效”。
  保留既有待应用目标供“应用”重试，不把成功文件回滚或显示成什么都没发生。
- 若默认快捷键已生效但旧注册释放失败，沿用既有清理状态和应用重试，分别说明当前活动组合与未完成操作。
- 恢复结果不要求重新启动应用；界面按实际生效语言刷新，窗口保持打开，不自动关闭贴图或发起截图。

## 7. 模块和接口范围

| 位置 | 变动 |
| --- | --- |
| Common 日志 | 窄目录查询、历史清理结果与同步入口；安全私有助手可与退出清理复用，保持退出停写语义。 |
| Application | 目录打开、单个历史清理 worker、操作状态与完成通知、退出协调，继续在 app_callbacks.cpp 组装跨模块回调。 |
| Settings | 维护页按钮、确认与状态、六字段默认候选及立即提交编排，沿用语言/自启/快捷键失败重试。 |
| 资源与测试 | setting_windows.json、ui_text.json，中英日说明及相应镜像测试/CMake。 |

不暴露 Logger/LogOptions，不新增第三方库；Settings 不包含 Logger 私有头。
WindowRenderer、Capture、Graphics、Export、PinWindow 内部实现不因本方案扩展。
恢复默认与“退出并清理”是不同用户动作，不能复用退出动作来恢复设置。

## 8. 小步骤施工计划

获批后分三步，由子 Agent 监督并在每步检查 diff：

1. Common 历史清理和只读目录入口，先做临时目录、当前流连续写及失败边界测试。
2. App 单任务协调与维护页，接入打开目录、确认清理、完成提示和退出回收，验证不影响其他草稿。
3. 六字段立即恢复、明确确认文案、系统生效重试及完整相关回归，更新文档和 Release 产物。

任何实质性扩大恢复范围、改变日志保留语义或修改其他系统状态都需重新提交审核。

## 9. 验证与验收

- 日志：只删除识别的历史普通文件；当前文件前后继续追加且内容不丢；未知文件/子目录/链接保留；
  目录缺失、权限不足、占用、候选消失、部分删除失败、清理期间轮转和并发写、取消及重试。
- 生命周期：重复点击只启动一个任务，设置关闭/重开、旧操作编号、完成通知失败、退出取消并 join，
  worker 不访问失效窗口或重启已经关闭的日志服务。大目录情况下设置窗口仍能处理交互。
- 恢复：六项从默认资源准备；未知字段、首次欢迎标记与目录记忆保留；非法草稿可被确认恢复替换；
  取消/坏默认/坏用户文件/只读/外部冲突保留原草稿；同值字段也必须检查冲突。
- 副作用：快捷键冲突阻止整批保存、写失败撤销候选、默认值已保存但运行状态未生效仍可恢复，
  语言/自启应用失败保留明确状态与重试；自动测试不写真实用户启动项、不删除用户真实日志。
- UI：维护操作不被无效草稿阻断或暗中应用草稿，真实点击确认流程、中英日、键盘与多 DPI。
- Debug /W4 /WX、Release、相关模块回归及必要全量；产物只在约定目录，历史贴图层级测试问题独立记录。

## 10. 设计复核

子 Agent 已只读核对 Logger 当前停止/轮转语义，以及 Settings 的默认候选、条件提交和系统副作用路径。
用户选择保留当前日志后，已放弃候选新日志切换方案，收口为历史清理；复核认可最小 worker 与结果所有权设计。
本稿纳入“同值默认也要复核运行状态”“系统副作用不能伪装成原子回滚”“通知失败不能丢结果”等意见。
批准后已按三步实施，新增 Common 入口、App 单任务与维护页；交叉复核结果及边界修正已纳入实现。

# OCR 截图文字识别设计（已批准）

日期：2026-09-25。状态：用户已明确同意方案并批准施工。文件中的 v0.4 为规划标识，不承诺下一次发行版本号。

## 1. 目标和现状

v0.3.0 已完成截图标注、安装和检查更新。本阶段实现本地截图文字识别、可编辑结果及复制，随后才进入文本翻译和图片翻译。
沿用产品需求第 12 节：Tesseract + Leptonica；fast/best 两套各含 chi_sim、eng、jpn；默认 fast 与 chi_sim+eng+jpn；运行时离线。
方案设计时仅有 OCR 构建开关和 vcpkg feature，尚无识别界面；目前实现状态见实施记录。

本阶段不加入云 OCR、翻译、自动上传、后台自动下载模型、表格重建、PDF 导入或专门手写识别。常规横排截图为首轮质量基准；竖排、旋转与复杂版面记录效果，不承诺专门优化。

## 2. 用户交互

1. 完成框选后，工具栏提供“识别文字”。绘制、原位文字编辑或属性事务尚未结束时，沿用现有输出准入规则，不能识别未提交的预览。
2. 点击时固定选区与已提交标注，生成与保存、复制相同的最终图像。因此马赛克、遮挡及添加的文字也参与识别，不回退到被遮挡的原始内容。
3. 显示非模态结果窗口，状态依次为准备、加载模型、识别、完成／无文字／失败；不显示虚假的匀速百分比。识别阶段在后台进行，截图编辑器继续保留且可以操作。
4. 结果为可编辑多行文字，支持选中、复制、粘贴、换行和控件内撤销；识别完成不自动写剪贴板；点击“复制全部”才复制当前修改后的内容，复制成功不关闭截图。
5. 一个截图会话只保留一个结果窗口；再次点击工具栏入口只激活已有窗口。窗口注明“基于点击识别时的截图；调整选区后，关闭此窗口并重新识别”。首版不增加自动重识别或结果历史。
6. 关闭结果窗／前台结果窗 Esc 仅关闭结果并取消其任务，原选区、标注和历史保留。IME 正在选字时先交给 IME。截图会话结束、输出完成导致截图关闭或显示拓扑失效时，同时关闭结果并取消任务。
7. 关闭后立即重开，若旧任务仍在不可中断的阶段，显示“正在结束上次识别，请稍后重试”，不排队、不启动第二份识别实例。
8. 结果窗使用独立宿主窗口生命周期，不把某一可销毁遮罩 HWND 作为唯一生命周期保障。结果窗在本会话遮罩上方；点击截图可返回编辑，工具栏入口可重新激活结果。
9. 结果窗为前台时 Ctrl+C/V/Z/A 和 Enter 归文本编辑器，Ctrl+S 不触发截图保存；全局截图快捷键在已有截图会话内不新建或销毁当前会话。必须经实际焦点、窗口归属及输入法状态判定，不仅检查某个缓存布尔值。

设置新增 OCR 页：模型档位 fast／best；识别语言“中英日混合／简体中文／英文／日文”。使用现有 Settings 保存及错误提示，默认值保持原需求。参数在任务提交时复制，修改设置只影响下次识别；界面语言和识别语言独立。

## 3. 已有能力与缺口

| 需求 | 已核对的已有入口 | 缺口与处理 |
| --- | --- | --- |
| 冻结帧裁切、HDR 转换、标注合成 | App::GenerateAnnotatedSelection、SelectionOutputRenderer::Render、SdrSelectionFrame | 直接复用正式输出，不抓取遮罩或预览；不另建色调映射 |
| 输出准入与代次 | CanSubmitToolbarCommand、既有会话及标注事务保护 | OCR 增加命令适配；异步任务不塞入仅同步 Copy/Save 的 CaptureCompletion |
| 普通窗口 | WindowRenderer::LoadLayout、Show、ProcessDialogMessage、SetStatus、SetEnabled、RequestClose | 新布局和业务绑定；不自建控件工厂、窗口循环、字体或 DPI 系统 |
| 多行编辑 | WindowRenderer::BindString；edit_support；原位 InlineTextEditor 的输入处理可参考 | 普通 edit 当前单行，新增可选 multiline、可视行数及垂直滚动；公共消息路由让 Enter/IME 先交给多行编辑；不拿原位标注编辑器代替普通表单 |
| 文本剪贴板 | Export::CopyImageToClipboard；私有 ClipboardMemory、ClipboardSession、ClipboardApi | 在 Export 扩展 CF_UNICODETEXT 写入入口，复用会话和内存所有权逻辑 |
| 配置、本地化、错误窗 | Settings 既有事务、GetUiText、公共 MessageDialog | 新增业务键和文本，通过 Application 窄回调适配，不建立第二套设置或提示机制 |
| 可选依赖与打包 | OPEN_ST_ENABLE_OCR、vcpkg feature、release_helpers 共享 staging 和清单 | 接入真实目标及六份模型；复用 DLL 闭包、资源校验、ZIP/Setup 和安装清单 |
| 文件校验与保护 | Common 文件租约／JSON；Update 内部下载哈希实现 | 不让 OCR 依赖 Update；核对通用哈希实现可否最小提取到 Common 并迁移原调用，禁止拷贝第二套算法 |

结果编辑不改变 Annotation 文档或截图 Ctrl+Z 历史；结果窗草稿与 OCR 原始结果语义不同，各有明确所有者。

## 4. 模块职责与依赖

新增 Application/OCR（OpenST::OCR），内部按职责拆分模型目录、图像预处理、引擎和任务实现，不预建空模块。

| 模块 | 拥有的状态和操作 | 允许依赖／禁止职责 |
| --- | --- | --- |
| OCR | 自有 CPU 输入、模型选择与验证、预处理、TessBaseAPI、工作线程、请求编号、取消及只读原始结果 | 标准库、Windows SDK、Common、Tesseract/Leptonica；不依赖 Graphics、Settings、Export、Localization，不创建窗口 |
| Application 私有 OcrResultWindow | 可编辑草稿、结果窗绑定、已消费请求编号、窗口生命周期 | WindowRenderer；复制和文本查询通过窄回调；不持有引擎或另建任务状态机 |
| Application 私有 OCR 会话协调组件 | 截图会话与结果窗口的关联、快照提交和失效协调 | 消费 OCR 与现有截图公共接口；不传完整 App 指针，不重写图像或识别算法 |
| App | 命令分派、设置及像素视图适配、会话关闭通知、消息路由 | 只编排，不拥有第二份 OCR 任务／识别文本／取消状态 |
| Graphics | 正式选区图像及标注合成 | 保持原职责；不添加 OCR 预处理、模型知识或 Tesseract 依赖 |
| WindowRenderer | 多行表单控件、布局、输入法、焦点和通用生命周期 | Common 与系统；无 OCR 设置键或识别状态 |
| Export | Unicode 文本发布与系统剪贴板内存所有权 | 保持现有依赖；不理解 OCR 请求或识别语言 |
| Settings／CaptureToolbar | OCR 参数表单／新增按钮及启用状态 | 沿用原有依赖；Toolbar 不承载结果窗或业务状态 |

依赖方向：Application → OCR；OCR → Common/Tesseract/Leptonica；Application → Graphics/Export/Settings/CaptureToolbar/WindowRenderer；不新增兄弟反向依赖。
输入公开类型由 OCR 自己定义（宽、高、stride、BGRX 只读视图），提交时完成一次有界复制，后台不借用 SdrSelectionFrame 或 GPU 对象。首版接受一次复制成本，记录峰值内存；不为消除复制扩大所有图像模块的公共类型。

## 5. 数据流与线程生命周期

固定选区与标注 → GenerateAnnotatedSelection → 独立 SDR 图像 → OCR 自有输入 → 模型验证 → Leptonica 预处理 → Tesseract → UTF-8 原始文字 → UI 一次性填入编辑草稿。

- 正式图像合成仍在现有图形所属线程完成，只在生成阶段持有输出准入保护；不把已有 D3D 上下文直接跨线程共享。该准备阶段的耗时单列测量，不能将“识别后台执行”写成整个点击流程绝无 UI 停顿。
- 使用单工作线程、最多一个活动任务；模型初始化、预处理、识别均归该线程。延迟加载，启动应用不预载六份模型；模型实例只缓存当前档位和语言组合，切换时释放旧实例。任务结束释放像素和识别页面数据，避免多份大型图像常驻。
- OCR 模块唯一维护请求状态：Idle → Preparing/Running → Succeeded/Empty/Failed，取消则先撤销发布资格，工作结束后回到可接受状态。窗口是否存在不等于引擎是否空闲。
- 窗口关闭立即取消和失效，不在关闭回调中 join。协调组件和工作线程由应用持有至后台结束，禁止 detached 线程访问 App/窗口。新任务无隐式重试、无无界队列。
- 识别使用引擎的合作取消监视器，在文件读取、预处理各阶段也检查取消。模型初始化及部分版面分析无法保证立刻中断；不得 TerminateThread，不能声称有硬性终止时限。
- 退出先禁止新任务、失效结果并请求取消，继续处理必要消息直至后台完成后再释放引擎和日志；不可中断阶段可能延长退出，需实测并报告，不以 UI 阻塞等待隐藏问题。
- 工作线程发布不可变结果并通知稳定消息接收者；消息仅携带编号，不传悬空窗口指针。接收时核对任务、窗口和会话代次；失败投递有可补收的完成状态，不能永久停在识别中。
- 成功只填充一次编辑草稿，后续状态刷新不得覆盖用户修改或原生撤销栈。空白识别显示“未识别到文字”，与引擎失败区分；未成功结果不发布部分文本。

## 6. 引擎、模型与资源约束

- 沿用当前 vcpkg baseline，不顺手升级整个依赖树；由解析出的实际 Tesseract 版本核验 API。fast/best 使用 LSTM 引擎 OEM_LSTM_ONLY。
- 首版采用无方向检测的自动版面分析，不引入额外 osd 模型。输入保持原分辨率，完成正确 BGRX→引擎像素转换及必要边界处理；由基准决定是否加入轻量缩放／反色，不预设大量图像增强和多次识别回退。
- 初始防护建议：宽高各不超过 16384、总像素不超过 3200 万、结果不超过 100 万 UTF-16 单元；逐项检查跨度和乘法溢出。超限明确提示缩小选区，不静默缩小或截断文字。施工先测峰值后可收紧实现预算，改变用户可用范围需重新说明。
- 六份模型路径建议 resources/ocr/fast/*.traineddata 和 resources/ocr/best/*.traineddata。单一受版本控制清单记录官方仓库不可变提交 URL、文件名、大小、SHA-256 和许可证；实际提交、大小与哈希已固定在 packaging/ocr/models.json，模型仅存入构建缓存。
- 只有启用 OCR 构建才下载／校验／缓存模型。临时文件验证成功再进入缓存，失败终止构建；运行期只读离线资源，不用模型缺失触发联网下载。
- 运行期在加载选中模型前校验固定白名单和哈希，防止工作目录／环境变量改写模型来源；中文空格路径必须实测。验证至加载期间保护文件身份，必要时使用引擎文件读取回调读取已验证数据，不能“校验一个路径，随后加载另一个”。精确 API 可用性在首步技术验证确认。
- 截图、预处理图和正文不写临时文件、不写日志；禁止引擎调试导出与用户任意配置文件。只记录阶段、耗时、尺寸及错误类别。

官方依据：[Tesseract 文档](https://tesseract-ocr.github.io/tessdoc/)、[模型类型](https://tesseract-ocr.github.io/tessdoc/Data-Files.html)、[预处理建议](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html)、[取消监视器声明](https://github.com/tesseract-ocr/tesseract/blob/5.5.1/include/tesseract/ocrclass.h)。监视器不覆盖所有版面分析阶段，不能把它当作即时终止保证。

## 7. 构建与发布

按用户后续修订，构建脚本顶部固定 `$EnableOcr = $true`，Debug/Release 默认包含 OCR；候选包使用 build.ps1 -Configuration Release -Package -Installer。关闭 OCR 时直接把变量改为 `$false`。关闭时不显示无效 OCR 入口，不携带模型或 OCR DLL。
复用同一次 Release staging，同一份六模型和运行依赖进入 ZIP 与 Setup；纳入文件哈希、安装校验、资源备份和卸载清单，不创建第二条打包流水线。
test.ps1 同样以脚本顶部固定变量默认启用 OCR，使用独立 feature profile，保持模块／case 位置参数；显式修改变量为 false 才运行基础配置。
同步 THIRD_PARTY_NOTICES 和许可证；报告 DLL、fast、best、运行库分别占用的体积。超过体积目标不擅自删模型，公开发布另行授权。

## 8. 分步施工与验收门槛

1. 基础验证：固定模型清单、恢复已声明的依赖，验证实际 API、中文路径、模型校验／读取、取消与退出行为；测冷加载、内存及模型体积。若必须改为独立进程或更换引擎，属于实质偏离，重新审核。
2. OCR 核心与测试：输入边界、六模型、混合及单语言、真实样例、空结果、取消／错误／晚结果；同时补公共多行控件和 Export 文本复制，各归本模块测试。
3. 应用闭环：设置、按钮、非模态结果、焦点、会话失效与恢复，复用正式截图输出；不因识别而重新抓屏或改变截图撤销历史。
4. 集成与打包：OCR 开／关 Debug/Release /W4 /WX，相关回归，干净启用构建，Setup/ZIP 资源一致性及离线识别；保留既有 D-066 的独立状态，不改断言伪装全绿。

真实样例至少覆盖中英日／混合、深浅背景、多行、小字、跨屏混合 DPI、HDR 输出和马赛克遮挡。标准测试使用仓库自有或许可明确的图片与真值，统计字符错误率；不以少量成功截图保证普遍准确。
性能以固定测试机、约 1200×800 常规正文选区记录点击至结果、图像合成、模型验证/加载、预处理、识别各阶段，冷/热分别测量；fast 典型 2 秒是既定目标，不提前标记达标。best 记录实际耗时。
人工重点：识别时编辑、结果 Ctrl+C/Z/Enter 与 IME、取消后立刻重开、截图关闭、跨屏结果窗口层级及旧任务晚到、复制失败保留文字、缺失/损坏模型不误报空白。

## 9. 方案复核与变更边界

子 Agent 已只读复核职责和复用范围，认可整体方向，要求补齐：公共多行 Enter/IME 路由、异步取消不得阻塞关闭、单任务寿命、结果草稿不被刷新覆盖、真实焦点与遮罩层级、统一打包以及测试位置参数兼容。本稿已纳入这些约束，并经子 Agent 全文收尾审核通过；此结论不代替用户批准。
用户于 2026-09-25 批准施工，按本方案实施。基准确认轻量 2 倍缩放改善小字识别，已在 OCR 内对不超过 1600×1200 的输入接入，仍校验扩展像素预算，只执行一次识别。施工与验证结论见 [实施记录](../ocr-implementation-2026-09-25.md)；实质偏离仍须重新审核。

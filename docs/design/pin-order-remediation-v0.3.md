# 0.3.0 贴图层级最小整改方案

状态：用户已批准缩小为测试与问题记录纠正；生产优化暂缓。日期：2026-09-14。
依据：[贴图层级验证报告](../pin-window-order-validation-2026-09-14.md)。

用户实际使用未感受到层级问题，验证也未复现恢复失效，因此不将原两项失败称为两个功能故障。
本轮只纠正测试和记录，子 Agent 已复核该缩减范围：

- 第一项移除绝对空前驱前提，独立核对相对顺序、置顶和命中；保留原名称、10 次调用及零请求断言。
  已确认冗余仍如实报告失败，不禁用、不跳过、不修改通过阈值，也不宣称优化已完成。
- 第二项用普通窗口形成实际重叠，验证有效干扰、模态恢复后的顺序、置顶及命中；不要求系统前驱为空。
- 对对应桌面测试目标设置串行约束。生产源码、公开接口和产品链接依赖不变。
- 第 3 节生产整改、第 4 节依赖新查询助手的分类测试，以及第 5 节零冗余验收均暂缓；

- 本轮执行 Debug /W4 /WX 构建、PinWindow 模块回归并更新记录；原始验证数据保留为历史证据。

以下为暂存的完整技术提案，后续恢复生产优化时需重新确认施工范围，不代表当前获批或已完成。

## 1. 整改目标

- 消除隐藏系统辅助窗口引起的无效层级调整：已经满足业务顺序时，重复 RepairOrder 不再发送位置请求。
- 保留可见窗口插入、可见覆盖及贴图置顶位丢失时的恢复能力。
- 让测试分别验证真实业务要求，不再用原生前驱必须为空替代可见性和层级判断。

已验证的基线：原两项测试三轮均失败；独立探针 90 次修复均多发 1 条上层位置请求。
前驱为 Explorer 的 cloaked ThumbnailDeviceHelperWnd；24 个受控模态恢复场景均恢复正确顺序和测试点命中。
本次针对确定的冗余及测试判据整改，不宣称修复尚未证实的闪烁、持续死循环或所有跨进程置顶兼容问题。

## 2. 产品规则保持

- 本程序贴图仍按唯一业务列表排序，普通点击、聚焦、拖动和缩放不改变列表顺序。
- 菜单手动提层只改变本程序贴图顺序，新贴图仍追加到顶部。
- 保留 WS_EX_TOPMOST，以及模态、截图、退出、同步重入等既有门禁。
- 保留原事件触发位置和 SetWindowPos 的不移动、不缩放、不激活、不调整 owner 顺序标志。
- 不增加抢顶定时器或持续收敛循环，不操作其他程序窗口，也不要求压过所有特殊系统窗口。
- 不修改贴图像素、透明度、缩放、输入资格、截图/保存或恢复模态的协议。

## 3. 生产代码整改

### 3.1 查找需要参与排序的前驱

在 PinWindow 内增加私有查询助手，供 RepairOrder 判断是否已经正确放置。
从目标窗口的 GW_HWNDPREV 开始向前检查：

| 当前节点 | 处理 |
| --- | --- |
| 正是当前业务期望的上一张贴图 | 立即返回该窗口，保留原有业务锚点，不再用隐藏/cloaked 过滤它。 |
| 已确认存在，IsWindowVisible=false | 跳过，继续向前。 |
| IsWindowVisible=true，DWM 查询成功且 DWMWA_CLOAKED 非零 | 跳过，继续向前。 |
| 其余仍存在的窗口 | 作为需要参与排序的前驱返回，包括可见外部窗口。 |
| DWM 属性查询失败 | 不能猜成隐藏；保守保留该前驱及查询不确定性。 |
| 完整走到链表顶部 | 返回“查询完整、没有相关前驱”。 |

先识别业务期望前驱，避免主循环仍使用一张自有贴图作为 previous、查询却过滤掉它而永远无法匹配。
这样可以保留当前业务目标窗口的筛选规则和 ConstrainOrder，无需另改激活或虚拟桌面语义。

不使用 ThumbnailDeviceHelperWnd 类名、Explorer PID、固定 HWND、1×1 尺寸或其他白名单。
本轮不新增按矩形相交过滤可见窗口的策略：可见外部窗口仍按既有行为参与层级恢复。

### 3.2 遍历与失败边界

- 返回值明确区分“完整且无前驱”与“不完整”，不能都用 nullptr 表达。
- 每次查询有固定步数上限，拟定 2048；自环立即中止，长环或异常链通过上限终止。
- 节点销毁、句柄失效、无法继续遍历或达到上限时返回不完整；不把未知状态当作已正确放置。
- 查询不是跨进程原子快照，不保证其他程序在返回后不改变窗口；沿用下一次既有事件重新核对。
- 不完整时最多沿用本轮一次保守位置设置，不新增“重试直到前驱为空”的循环。
- 正常跳过隐藏窗口不写警告日志；属性失败采取保守判断，不增加高频弹窗或持续日志刷新。

### 3.3 修改 alreadyPlaced

仍从业务列表顶部向下处理：

1. 先检查目标自身 WS_EX_TOPMOST；该标志丢失时必须修复。
2. 第一张业务贴图：查询完整且没有需要参与排序的前驱，才视为已放置。
3. 后续贴图：查询完整且返回上一张业务贴图，才视为已放置。
4. 已满足条件则不调用 SetWindowPos；否则沿用现有设置方式，每张最多尝试一次。

例如原生链为“cloaked 系统辅助窗 → 上层贴图 → 下层贴图”，将被识别为无需调整。
如果变为“上层贴图 → 可见外部窗口 → 下层贴图”，下层仍必须调整。
如果可见窗口盖到上层之前，或下层丢失置顶位，仍执行原有修复。

### 3.4 依赖和文件

- 修改 PinWindow/source/pin_window_manager.cpp 的前驱判断。
- 可新增 private/pin_window_order.h 与 source/pin_window_order.cpp，隔离查询及最小系统查询替身；不新增公开 API。
- PinWindow 的 CMake 显式 PRIVATE 链接 Windows SDK 的 dwmapi，登记实际新增文件。
- 不新增第三方库，不扩展 Common、WindowRenderer、Application 或 PinRenderer。

## 4. 测试整改

### 4.1 保留第一项测试的核心要求

保留 repeated_correct_order_emits_no_position_requests 的名称和“正确顺序后 10 次修复，位置请求数为零”。

- 移除将所有自然系统窗口排除在外的原生前驱空断言，改为独立检查贴图置顶位、业务相对顺序和有效前提。
- 准备正确顺序后再建立计数器，避免把初始化的必要位置操作算成冗余。
- 使用自有隐藏置顶测试窗口验证“不呈现的前驱不会触发调整”；真实环境中的 cloaked 窗口作为额外观测。
- cloaked 不依赖本机必须出现某个 Explorer 辅助窗：通过私有查询边界测试可控的 cloaked 返回。
- 必须覆盖隐藏窗口插在两张贴图之间，以及业务期望前驱自身被标记 cloaked 时仍保持原比较锚点。

### 4.2 强化第二项的实际干扰

保留 modal_exit_repairs_external_window_interleaving 的名称；将 1×1、无实际重叠的 STATIC 干扰换成自有普通窗口。
采用部分重叠的两张贴图，保留下层独露点和上层采样点。

| 场景 | 恢复前必须证明 | 恢复后检查 |
| --- | --- | --- |
| 可见窗口插在两图之间 | 原生顺序确实插入；下层点命中干扰窗、上层点命中上层贴图 | 两张贴图顺序、置顶位和各自采样点命中恢复 |
| 可见窗口盖到顶部 | 两个采样点均命中干扰窗 | 同上 |
| 下层失去置顶位 | WS_EX_TOPMOST 确实清除 | 置顶位、顺序和命中恢复 |

必要修复要求确实产生位置请求，但不把原先每次 2 条写成必须值；整改后可能只需调整一张贴图。
恢复后继续调用 10 次 RepairOrder，要求没有冗余请求。
跨进程场景保留独立兼容性探针观察，不新增“必须压过所有其他应用置顶窗”的绝对验收要求。

### 4.3 查询和异常测试

私有系统查询替身覆盖：隐藏、cloaked、可见、DWM 失败、节点失效、自环、链过长、业务锚点保留。
这些用例测试具体输入输出；真实层级回归通过独立的窗口属性和物理点命中判断结果，不能只调用被测助手给自己判通过。
Windows 可见标志、DWM cloaked、普通窗口命中与实际像素/闪烁分别说明，不能相互替代。

### 4.4 防止测试互相干扰

涉及真实窗口层级的 PinWindow 测试执行串行约束，复用现有 gate 测试的 RUN_SERIAL 思路。
必要时在现有含窗口集成测试目标的 gtest_discover_tests 上统一指定 RUN_SERIAL，不改变模块筛选名和原 case 名。
不把全仓测试全部改成串行。其他用户程序仍可能改变桌面，失败时记录其可见/cloaked/几何状态用于诊断，不直接跳过。

## 5. 施工拆分与验收

获批后分三步，由子 Agent 监督：

1. 实现私有前驱查询及可控分类测试，明确完整/不完整结果。
2. 替换 RepairOrder 判断，整改原两项测试的前提和结果检查，增加串行约束。
3. 重跑原模块及独立探针，完成 Debug /W4 /WX、Release、全量回归与记录。

具体完成标准：

- 同样的原始几何及 Per-Monitor V2 探针，在没有新可见干扰时，原 90 条冗余请求降为 0。
- 原 24 个有效干扰场景继续恢复顺序、置顶位和测试点命中，不能因优化忽略可见外部窗口。
- 原两项及新增分类/边界测试通过；再运行全量，既有条件跳过如实列明，失败不能以重试或删除断言掩盖。
- 保留普通点击不提层、手动提层、拖动缩放、模态 owner、截图暂停和关闭回收的相关回归。
- 不以零请求推断没有闪烁；若要宣称视觉体验改善，需要独立实际观察。

## 3. 页面和交互

已新增“截图与存储”页，沿用左侧描述、右侧控件的排列：

| 左侧功能 | 右侧控件 | 生效时机 |
| --- | --- | --- |
| 选框颜色 | #RRGGBB 文本输入框，默认 #000000 | 应用成功后的下一次截图 |
| 默认保存格式 | JPEG / PNG 下拉框 | 应用成功后的下一次截图或贴图保存 |
| JPEG 质量 | 滑条＋数字输入框，1–100、步长 1，默认 95 | 下一次实际选择 JPEG 保存 |

JPEG 质量在默认格式为 PNG 时仍保留可编辑，并说明“仅 JPEG 保存使用”；用户可能在保存对话框临时选择 JPEG。
质量 100 不标成“无损”。不增加自动保存、保存历史、压缩率承诺或预计文件大小等功能。

- 完整合法输入立即更新内存草稿并更新“应用”状态，不等待失焦才通知。
- 允许正常编辑过程中的暂时空值和未完成输入，但显示字段错误并阻止保存；不能偷偷提交上次合法值。
- 应用和确定共用一次批量条件提交；取消只丢弃未提交草稿。
- 恢复本页默认经确认后修改本页三项草稿，仍需应用；默认资源无效则保留原草稿并提示。
- 切换页签保留草稿；重新加载经现有确认流程丢弃草稿，读取失败不覆盖文件或冒充加载成功。
- 颜色只提供直接文本输入，不增加色板、取色窗口或屏幕吸管；标签、格式提示和错误使用中英日资源。

### 颜色输入校验

- 必须是 # 加六个十六进制字符，例如 #12ABEF；接受 a–f/A–F，不支持透明度。
- 拒绝空值、缺 #、位数错误、非十六进制字符、前后空白、#RGB 简写、颜色名称和八位颜色。
- 逐次输入保留原始文本；半个色值可以暂存在输入框，但显示字段错误并阻止应用/确定，不使用上次合法值代替它保存。
- 规范大写在显式提交的候选批次中完成，不在用户键入时改写文本或移动光标；保存失败保留用户原输入。
  仅修改字母大小写也按一次显式文本修改处理；保存成功后显示规范值。打开已有小写合法值不自动改写文件。

### JPEG 质量同步

- 数字输入只接受 1–100 的十进制整数；滑条最小 1、最大 100、步长 1。100 仍表示有损 JPEG 的最高质量级别。
- 合法数字立即更新滑条与内存草稿；拖动滑条或使用其键盘操作立即更新数字框与草稿。
- 空值、负数、小数、非数字、溢出和越界不夹取、不改成默认值；保留原输入和错误，并阻止提交。
- 数字无效时滑条可保留最近合法位置，但该位置不代表当前编辑内容有效。
  只有用户主动操作滑条时，才用明确选择的新值替换非法文本并清除错误；程序同步或语言刷新不得清掉原输入。
- 输入变化通知必须包含“有效／无效／尚未输入完整”的状态，不能只把合法整数通知宿主。

## 4. 设置数据及默认兼容

| 动态设置键 | 类型 | 默认值 | 语义 |
| --- | --- | --- | --- |
| capture.selection_border_color | string | #000000 | 沿用既有键；严格六位 RGB，不包含透明度；接受大小写，显式编辑后保存规范大写。 |
| export.default_format | string | jpeg | 新键，固定 token 为 jpeg / png，与界面语言分离。 |
| export.jpeg_quality | integer | 95 | 新键，拟定范围 1–100，拒绝浮点、bool 和超出可表示范围的整数。 |

新增默认值写入 resources/default_settings.json。旧用户文件缺键时显示并使用有效默认，不因读取或打开设置而补写用户文件。
新安装仍按既有初始化规则创建完整默认配置；既有保存目录与未知字段必须保留。

运行期使用类型化 Get/Set*Setting 接口及默认读取接口，设置名不增加枚举或注册表。
新增整数默认读取接口仅在确有调用需要时增加；不公开 JSON 文档或跨模块文件句柄。

### 非法配置的显示与恢复

- 文件读取失败：按既有 Common 失败返回及业务告警机制处理，不以缓存冒充成功。设置窗口没有可靠编辑基线时禁用提交。
- 字段缺失：使用默认，不使草稿变脏。
- 字段类型正确但业务无效（例如质量 999、未知格式、非法颜色）：保留用户意图并显示错误，要求修改或恢复默认。
  控件不能直接展示原值时，单独展示无效状态，安全预览不算已修复；不静默把 999 夹取成 100。
- 字段原始类型错误：可显示有效默认并明确标记“待修复”；点击应用才通过 requiredKeys 显式修复该字段。
  不能显示正确默认、却一直禁用应用使用户无从修复。
- 保存业务遇到格式/质量无效时，尝试相应有效默认并告警；格式与其默认均无效时无法确定初始格式，报告失败。
  质量与其默认均无效时记录本次质量不可用：实际选择 JPEG 则在写图像前失败，实际选择 PNG 则不依赖该质量。
  失败保留截图或贴图供重试，不能让无效 JPEG 质量阻断不使用该参数的 PNG 编码。
  不以硬编码值掩盖损坏资源，不自动写回用户文件。边框继续保留现有最终黑色回退，不重写截图颜色算法。

## 5. 模块边界

| 模块 | 本轮职责 |
| --- | --- |
| Settings | 三个设置键、草稿、默认来源与字段状态、整数编辑、批量条件保存、页面绑定。 |
| Application | 提供共享参数校验/规范化回调，读取一次保存所用的固定参数，连接对话框与 Export；回调仍集中在 app_callbacks.cpp。 |
| Export | 消费明确的格式与质量参数，验证参数并执行 WIC 编码；不读取 Settings、不直接显示界面。 |
| WindowRenderer | 新增通用文本编辑、整数编辑与滑条绑定，提供即时变更和无效输入通知、布局、焦点与错误显示；不认识业务键或保存命令。 |
| Graphics | 继续消费现有选框颜色接口和冻结帧；本轮不改捕获、HDR、像素合成或显示流程。 |

Application 可增加私有 capture_storage_options.h/.cpp，集中格式 token、质量范围及颜色输入的业务验证与选项组装。
Settings 通过 Application 注入的窄回调调用同一语义规则，Application 不包含 Settings 私有头，兄弟模块不互相依赖。
颜色格式规则在业务侧统一验证，由 Settings 使用 Application 注入的回调消费；Renderer 只处理文本编辑，不内置颜色业务规则。
不新增第三方包，也不扩展 Common JSON 管理器；不引入颜色选择器或其额外依赖。

### Renderer 扩展清单

- 复用已实现的 row 与 select。
- 数字控件提供通用整数读取、编辑状态和即时回调；范围从布局/绑定给出，最终业务验证在宿主。
- 普通文本编辑支持原始文本读写与即时变更回调；十六进制校验留给宿主，覆盖取消、无效中间输入和失焦。
- 滑条与数字框通过绑定共享同一草稿，区分程序刷新和真实用户输入，拖动即时同步，键盘导航不误提交设置。
- RefreshTexts 不重建草稿或吞掉未完成输入；明确重新加载/恢复默认才使用 RefreshValues 替换编辑内容。
- 新控件不改变现有语言下拉、快捷键录入、欢迎窗口和模态提示的行为。

## 6. 整数草稿与一次提交

扩展 SettingsEditSession 私有整数编辑能力，继续保留原始字段、有效基线、当前草稿三层数据。
合法 signed/unsigned JSON 整数在业务层转换为可表示的 int64_t；数值草稿和默认比较使用统一整数语义。
原始字段仍保留存在性与类型信息以进行外部冲突检查，整数、浮点和 bool 不能混同。
不得因默认资源中的正数被解析为 unsigned，而输入得到 signed 95，就把恢复默认或无修改判断判成失败。

提交顺序：完成各页业务校验及已有快捷键候选准备 → 一次 Common 编辑写入 → 无异常完成快捷键切换 → 原有语言/自启副作用。
新增三个字段不单独调用多个 Set 拼成伪事务，不绕过同键冲突规则；任意需提交字段冲突或写入失败时整批不发布。
颜色、默认格式与质量采用后续操作读取，无需在保存后打开新的系统设置或重建当前截图。

## 7. 一次保存使用的固定参数

在截图/贴图的保存业务进入忙状态后、显示保存对话框前，读取并验证本次默认格式与 JPEG 质量，保存为局部只读值。
质量读取结果同时保留可用性，直到用户选定实际格式后决定是否必须使用；PNG 不因质量无效而失败。
整个对话框与编码过程复用这些值，期间不再次读取设置。默认格式决定初始选择，用户临时选择决定本次实际格式。
本进程 UI 线程在读取期间不泵消息，但既有动态 getter 不是跨进程多字段事务；不宣称外部同时改文件时可取得原子配置快照。

Export 已增加其自有 ImageEncodingOptions，包含格式和整数质量；产品调用方、私有编码/文件替身及测试已统一更新。
避免留下一条继续写死 95 的产品路径。PNG 编码忽略 JPEG 质量，复制完全不调用此参数路径。
JPEG 参数必须在创建/覆盖输出文件前验证；保持先内存编码后写文件，编码失败不触碰目标。
WIC 使用 float(quality) / 100.0F；本轮不改变色度采样、sRGB 元数据、HDR→SDR 或输入像素格式。

截图保存取消/失败保留选区和冻结帧；贴图保存取消/失败保留原图。窗口暂停、有效 owner、退出与显示失效保护保持原语义。
只在图像文件保存成功后记住目录。记目录失败仍属于图像已保存后的告警，不把成功图像误报成写入失败。

## 8. 保存格式和文件名一致

- 同时设置初始文件类型索引、默认扩展名和建议文件名后缀。JPEG 默认为 .jpg，PNG 为 .png。
- 用户在保存窗口临时切换类型，只改变本次类型与对应扩展，不修改 export.default_format。
- JPEG 下已有 .jpg/.jpeg（大小写不敏感）均有效；PNG 下 .png 有效。
- 无扩展名时补所选格式的默认后缀；不匹配或未知后缀按所选格式修正，保留目录及文件主体。
  JPEG 下“图片.png”成为“图片.jpg”，PNG 下“图片.jpg”成为“图片.png”；不生成双后缀来掩盖不匹配。
- 所有修正在原保存窗口内完成。切换类型优先使用系统扩展联动，最终返回前再次验证路径与格式。
- 如 OnFileOk 发现需要修正，更新窗口内文件名并返回 S_FALSE，显示修正原因，让用户对最终路径再次保存确认。
  不宣称此事件早于所有系统覆盖事件；修正后必须重新经过最终目标的覆盖确认，不能复用旧路径的许可。
- Show 返回 Accepted 后仅使用系统确认过的最终路径，不再偷偷替换扩展名。取消或事件错误保持既有 Cancelled/Failed 返回语义。
- COM 事件对象及 Advise cookie 使用明确生命周期，在成功、取消、异常路径都解除订阅，不泄漏引用或持有已关闭窗口。

本轮不承诺已有目标文件写入失败可恢复原文件；保留当前已记录的覆盖语义，不将其扩展为文件原子替换工程。

- 设置：旧文件缺键不写、原始类型错误、未知格式、非法颜色、整数负值/零/上界/溢出/浮点/bool，

  左右布局、中英日、Tab/Enter/Esc、长文本、小视口及混合 DPI，不重复引入快捷键录入通知问题。
- Export：质量 1/95/100 的实际 WIC 编码与解码有效性，固定纹理在不同质量下的输出变化；
  不以所有图片文件大小都单调增加作为断言。PNG 与复制像素语义不变，非法 JPEG 参数不触碰目标。
- Application：截图与贴图均传递相同规则生成的参数；模态期间外部改设置不改变本次已取参数；
  取消/失败/退出/显示失效仍由原准入和资源保护处理。自动化使用文件对话框及文件输出替身。
- 文件名：初始 JPEG、手动切 PNG、下次回到设置默认、大小写后缀、.jpeg、无后缀、多点文件名、
  自定义目录、后缀冲突、修正后目标已存在时的覆盖取消/确认。人工必须核对最终确认路径与实际写入一致。
- Debug /W4 /WX、Release 构建与受影响模块回归，必要全量验证；资源哈希和产物目录检查；
  历史两项贴图层级测试问题独立记录，不用跳过或改断言冒充解决。

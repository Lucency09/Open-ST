# 欢迎流程与当前用户开机启动方案

状态：用户已明确批准，代码已实施，最终构建与人工系统集成验收进度见 [实现进度](../implementation_progress.md)。日期：2026-09-09。

## 1. 范围与现状

对应进度表第 2 步：欢迎流程、自启开关、路径变化、退出清理、单实例及启动命令。
设计前 App 使用固定 Local 互斥体，第二次启动只提示已运行；main 不解析参数。
设计前 Settings 草稿和 WindowRenderer 只有字符串值绑定；本轮已增加布尔支持。
本轮不引入快捷键管理模块、截图工具栏、OCR 或翻译业务。

## 2. 模块位置

新增 `src/Launcher/Application/SystemIntegration`，目标 `OpenST::SystemIntegration`。
内部包含 StartupRegistration（当前用户启动入口）和 SingleInstance（互斥与固定启动命令转发）。
模块只提供系统能力和结构化结果，不读取业务 JSON，不直接弹窗；Application 私有链接并协调。
测试镜像放在 `testing/test/Launcher/Application/SystemIntegration`。

欢迎窗口放在 Settings 模块，使用 Common/WindowRenderer；布局以 Settings 内嵌 JSON 提供。
设置页继续读取 `resources/setting_windows.json`。
Common/WindowRenderer 只增加通用 checkbox 与 BindBool，SettingsEditSession 增加布尔草稿和条件提交。
Settings 通过 Application 注入的回调查询/应用自启，不依赖兄弟 SystemIntegration。

## 3. 系统入口

采用 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `Open-ST` 值，
内容为带引号的当前 EXE 绝对路径及 `--startup`。使用当前用户权限，实际触发时间为用户登录。
校验完整命令不超过 Run 文档规定的 260 字符，失败显示原因，不截断路径或创建额外启动方式。
只操作约定的本程序值，不枚举删除其他启动项；无法确认归属的冲突值报告冲突。
关闭时值已不存在视为成功；写入/删除后重新读取核验。

界面分别表达已保存意图、入口是否存在/路径是否匹配及操作失败；入口存在不能保证 Windows 实际允许运行。
不读取或修改未公开的 StartupApproved 二进制数据。
程序移动后，下一次手动运行新路径时提示修复；用户确认后更新入口。
外部删除入口时提示不一致，不在每次启动时自动重建；从而尊重用户在系统侧进行的修改。
旧路径失效后无法自行启动修复，这是便携程序的边界。

## 4. 欢迎与设置行为

新增布尔键 `onboarding.completed`（默认 false）与 `startup.enabled`（欢迎默认 true）。
默认值只是界面初始选择，读取默认设置不会创建启动项。
欢迎页展示默认快捷键 Ctrl+Alt+Q、自启复选框和隐私边界说明。
OCR 本地、文字翻译上传文字、图片翻译上传处理图片，明确标注尚未提供的功能为后续能力。
首次通过 --capture 启动也先完成欢迎，再执行一次截图；--startup 不跳过首次告知。
确认前按 X/Esc/取消：退出，不保存欢迎选择，不修改系统入口，下次仍显示欢迎。

确认后先条件提交用户选择与 onboarding.completed=true，再应用系统入口。
completed 表示用户已确认并保存欢迎选择，不表示系统自启已成功。
JSON 保存失败不操作系统；系统失败时提示“设置已保存，开机启动未生效”，提供重试或退出。
再次启动不重复欢迎，但检查并报告已保存意图与系统入口不一致，不静默重建。

常规设置页增加“登录后启动 Open-ST”复选框和自启状态文字。
勾选只修改草稿；应用/确定提交，取消丢弃未保存草稿。
先保存 JSON，再调用系统回调；系统失败保留待生效目标与重试入口，确定不自动关窗。
重试前核对保存值，避免旧窗口覆盖外部的新选择。已保存后的取消不撤销保存和成功的系统操作。
“关闭即删除”指成功提交关闭选项后立即删除入口；不会等到下次启动。
同批语言、自启提交先原子保存设置，再分别执行副作用，分别报告失败，不宣称跨 JSON/注册表原子事务。

## 5. 启动与单实例

| 启动方式 | 无现有实例，且欢迎已完成 | 已有实例 |
| --- | --- | --- |
| 普通启动 | 托盘常驻 | 请求打开设置 |
| --capture | 初始化后截图 | 请求截图 |
| --startup | 托盘常驻 | 静默退出 |

未知参数或互斥参数组合返回明确错误，不隐式触发截图。
使用包含当前用户 SID 的 Global 互斥体实现每用户一个实例，不阻止其他用户运行。
本地命名管道仅接收固定命令，限定当前用户访问、拒绝远程客户端，检查协议版本、长度和对端身份。
通信使用有限超时；首实例尚未就绪时有限重试，失败不放行第二实例。
后台接收线程只投递 App 消息，UI 线程判断可执行状态并处理；正在欢迎或忙于模态流程时拒绝截图，不积压过期请求。
接收侧读取原子暂停状态与代次；截图消息带代次，UI 再次核对，防止同步保存后才处理的旧请求执行。
Settings 通过 busyChanged 通知 Application；嵌套忙状态统一汇总，内层退出不会提前恢复截图。
设置请求在欢迎期间激活欢迎窗口。跨登录会话的同一用户按需求仍只允许一个实例，
但不跨会话执行截图或激活不可见窗口，提示实例位于另一会话；--startup 仍静默退出。
主实例判定提前到业务文件初始化之前，第二实例不创建或修改设置。

## 6. 退出并清理系统集成

托盘增加单独命令与确认窗口，可选删除日志；普通退出继续保留自启入口。
清理先保存 startup.enabled=false，再删除经核验属于本程序的启动入口；失败留在确认窗口供重试。
成功后阻止新业务请求，关闭截图/设置，注销热键，停止日志写入，再按用户选择清理本程序日志。
只删除实际日志目录内由本程序命名规则识别的日志文件，不删除用户设置、资源或其他文件。
日志清理期间保留可见确认窗口，失败可报告并选择重试或保留剩余日志退出；成功后移除托盘并退出。
当前没有贴图实例，后续贴图模块接入同一退出协调流程，不为此预建模块。

## 7. 施工步骤与验证

1. SystemIntegration：自启查询/写入/删除及路径校验，先用测试替身与临时测试注册表键验证。
2. 布尔草稿和 checkbox：验证类型、绑定 ID、取消、恢复默认与条件保存。
3. 欢迎及设置接入：验证先保存后生效、部分失败、重试、取消和状态展示。
4. 参数与单实例：双进程启动、就绪竞态、超时、忙状态、跨用户/会话边界。
5. 清理流程和联调：重复清理、系统失败、日志关闭后删除以及普通退出保留自启。

自动测试不注册真实登录启动项，不修改用户现有 Run 值。真实自启/退出清理使用显式人工集成用例，
单独记录执行前后的值及恢复结果；真实注销登录与系统启动禁用状态需要人工验收。
新增窗口沿用独立人工弹窗 case，无定时关闭；正常自动回归不等待人操作。
完成相应模块测试、Debug/Release 构建、资源打包及 git diff 检查。

实施时同步修复用户发现的早期启动语言问题：实例判定之后、任何普通启动错误提示之前，
Settings 通过 Common 只读已保存语言及资源默认值，第二实例不创建设置或日志。
运行时语言应用刷新已存在窗口及托盘；截图底层诊断保留在日志中，界面使用本地化错误键。
手动验收步骤与真实 Run 项的前后记录要求见 [开发规范](../development.md#欢迎开机启动与退出清理人工验收)。

预计涉及约 20～30 个新增/修改文件，主要为新模块、镜像测试及布尔 UI 支持，最终按实际实现记录。
子 Agent 已复核：补齐欢迎取消、实际状态、管道就绪竞态及日志失败可见报告后，范围与依赖合理。

## 8. 平台依据

- [Run 与 RunOnce](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)：登录触发、当前用户 Run 入口、260 字符限制。
- [内核对象命名空间](https://learn.microsoft.com/en-us/windows/win32/termserv/kernel-object-namespaces)：Global 与 Local 的会话范围。
- [命名管道权限](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights)：显式权限和访问校验。

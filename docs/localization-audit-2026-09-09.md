# 用户可见文本检查（2026-09-09）

用户指出重复启动提示一直使用英文，本次结合欢迎和自启施工检查用户界面取文及刷新路径。

## 根因与修复

原 App 先初始化 Localization（默认 en-US），再判断重复实例，之后才读取 Settings 的 ui.language。
因此重复实例在读取用户语言前就显示提示。现在先判断实例身份，再通过 Settings::ReadStartupLanguage
只读获取已保存语言；需要显示的参数、通信失败和跨会话提示均在语言应用之后生成。
只读入口不创建 settings.json，也不让第二实例写入用户设置。正常重复启动改为通知主实例打开设置。

## 检查结果

| 界面 | 取文与刷新方式 |
| --- | --- |
| 启动参数、实例通信和跨会话错误 | 初始化文本资源并只读应用保存语言后调用 GetUiText |
| 托盘提示 | App::RefreshLocalizedUi 重新取文并通知 Shell 更新 |
| 托盘菜单（含清理入口） | 每次展开重新调用 GetUiText |
| 隐藏消息窗口、截图窗口标题 | App::RefreshLocalizedUi 刷新现有窗口 |
| 设置标题、页签、标签、按钮、自启状态 | SettingsWindow::RefreshTexts 重新查询文本回调；状态和字段错误保留键而非旧译文 |
| 欢迎窗口及失败状态 | WelcomeWindow::RefreshTexts 通过回调重新取文 |
| 关于与截图错误窗口 | 使用动态文本函数；App 保存当前窗口的借用指针，语言改变时刷新。截图错误详情也保存文本键 |
| 清理确认窗口及失败状态 | 当前 Renderer 与状态刷新回调纳入 App 的语言刷新，关闭前解除借用 |
| 保存对话框的应用标题、格式名称 | 每次打开时 GetUiText；显示期间禁用设置窗口，防止模态过程中切换应用语言 |
| 系统 MessageBox 中的应用正文、标题 | 显示时 GetUiText；优先以设置窗口作 owner，避免显示期间切换语言 |

Settings 保存语言后通过 Application 回调 SetUiLanguage，再统一刷新已有窗口。
业务文件和系统入口写入失败仍与语言切换失败分开报告。

## 明确的边界

- 系统文件选择器的导航、保存按钮，以及 MessageBox 的系统按钮由 Windows 提供，遵循系统界面语言。
- 本地化资源本身完全无法加载时，启动只能使用固定中英日三语故障提示；此时无法通过损坏的资源翻译提示。
- Capture、Graphics、Export、系统集成中的底层诊断用于日志；向用户显示的是 Application 的本地化错误外壳。
- 语言代码、文件路径、版本号等数据不作为译文翻译。未完成翻译的语言继续按协议回退英文。

## 验证

- 只读启动语言测试验证未初始化设置时可读取保存值，且不会创建缺失的用户文件。
- 设置回归覆盖切换后状态文本刷新，以及语言和自启副作用的独立失败/重试。
- 简单弹窗回归在窗口打开期间切换文本函数并刷新，检查标题、正文和确认按钮；窗口退出和创建失败均清空借用指针。
- 本轮新增文本键补齐 zh-CN、en-US、ja-JP；扫描调用与布局中使用的相关文本键，未发现遗漏。
- 完整多语言视觉与跨 DPI 人工验收仍需用户操作，自动测试不等同于视觉验收。

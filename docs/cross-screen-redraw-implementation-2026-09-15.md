# 跨屏统一重绘整改收尾

日期：2026-09-15。状态：实现与自动验证完成，用户已确认原跨屏拖动掉帧问题解决，本阶段验收通过。
依据：[整改方案](design/cross-screen-redraw-v0.3.md)、[原始诊断](cross-screen-frame-pacing-report-2026-09-14.md)。

## 实现结果

- `App::RenderOverlays` 一次获取选区快照，`CaptureOverlaySession::Paint` 固定待绘制输出，
  在首屏绘制前处理整批已有更新区域，再依次给每屏一次绘制机会。
- 请求代次与每屏待重绘标记保留 BeginPaint 重入、绘制期间的新失效和嵌套 WM_PAINT。
  有效内部绘制通知即使没有普通更新区域也能触发；无新请求时不主动循环呈现。
- 渲染保护覆盖目标重建、同步完成命令、显示失效、窗口销毁、关闭和退出。
  图形调用返回后才释放 renderer／会话／模型，退出消息也在安全收尾后推进。
- Graphics 的绘制、Present(1, 0)、颜色验证、HDR 算法与输入捕获规则未修改。
  不添加诊断设置、后台渲染线程或新的第三方依赖。

## 生产逻辑的原生手势复测

复用原诊断的按钮／指针轨迹、显示配置和阶段定义，两个起点各三轮，每轮 16 秒，合计 6 组、24 个阶段。
使用当前生产 App 与会话实现；独立计时副本只增加记录，**没有替换调度、Present 参数或鼠标读取路径**。
原生按钮、自然鼠标消息、前台／焦点／捕获归属均核验；结束释放左键、清空捕获并恢复原指针。

所有阶段两屏提交次数一致，无图形错误、记录溢出或清理失败。

| 原先受影响的主屏阶段 | 整改前三轮提交率 | 生产整改后三轮提交率 | 整改后 P95 提交间隔 |
| --- | ---: | ---: | ---: |
| 副屏按住拖到主屏 | 20.01–24.56 次/秒 | 60.03–60.46 次/秒 | 33.15–33.21 ms |
| 副屏松开重按后，再按住拖回主屏 | 19.69–32.25 次/秒 | 60.05–60.29 次/秒 | 33.12–33.24 ms |

活动进程 CPU 约为一个逻辑核的 89–92%，未改善；约 33 ms 尾延迟仍在。
